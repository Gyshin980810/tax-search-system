# 세법 답변 검증 워크플로우 — tax-verify SKILL

## 역할
law-verifier 에이전트가 tax-generator 에이전트의 답변을 독립적으로 V1~V6 검증한다.
이 SKILL은 CLAUDE.md §6.4를 실행 가능한 체크리스트로 재작성한 것이다.

## 검증 항목 V1~V6

### V1: 출처 존재 확인

**통과 조건**: 답변에 인용된 모든 조문(법령명 + 조문번호)이 원본 TaxLaw[] 배열 안에 존재한다.

**실행 방법**:
1. 답변에서 인용된 법령명·조문번호 목록 추출
2. TaxLaw[] 배열의 `law_name` + `article_number` 필드와 대조
3. 하나라도 없으면 V1 FAIL

**실패 시**: 재검색 1회 → 여전히 없으면 `E-VERIFY-FAIL` 반환

---

### V2: 인용 무결성 (문자 단위 비교)

**통과 조건**: 답변에 포함된 모든 발췌 텍스트가 원문 TaxLaw.content와 문자 단위로 일치한다.

**실행 방법**:
1. 답변에서 인용 발췌문 추출 (따옴표 내부 또는 들여쓴 블록)
2. `Grep` 도구로 TaxLaw.content에서 해당 텍스트 검색
3. 퍼지 매칭 금지 — 띄어쓰기, 구두점 포함 정확 일치

**생략 표시 규칙**: `(…)` (괄호 안 점 3개) — 다른 형식 불인정 (`...`, `···`, `[중략]` 금지)

**실패 시**: 재생성 1회 → 여전히 불일치 시 `E-VERIFY-FAIL`

---

### V3: 라벨 적정성 (Trust Tier)

**통과 조건**: 각 인용문의 라벨이 Trust Tier에 맞다.

**규칙**:
- T1/T2 출처 → 🟢 직접 근거 가능
- T3 출처 단독 → 🟡 유사 사례만 가능 (T1/T2 없을 때)
- T4 출처 단독 → 🟡 또는 ⚪ 참고 자료만 가능
- T1/T2가 있는데 T3/T4에 🟢 붙이면 V3 FAIL

**실패 시**: 재생성 1회

---

### V4: 시점 라벨 (필수 부착)

**통과 조건**: 모든 인용 조문에 시점 라벨이 부착되어 있다.

**허용 형식**:
- `[현행]` — 답변 생성 시점 시행 중
- `[적용 시점: YYYY.MM.DD ~ YYYY.MM.DD]` — 특정 기간
- `[폐지: YYYY.MM.DD]` — 폐지된 조문

**실패 시**: 재생성 1회 (자동 부착 불가 — 정확한 시점은 법령 원문 기반)

---

### V5: 면책 고지 존재

**통과 조건**: 답변 하단에 다음 형식의 면책 고지가 존재한다.

```
[면책 고지] 이 답변은 공식 세법 API 검색 결과를 인용한 참고 자료입니다.
실제 세무 신고·의사결정은 반드시 담당 세무사·회계사의 검토를 받으시기 바랍니다.
```

**실패 시**: 자동 부착 (V5는 항상 PASS 처리, 누락 시 자동 추가)

---

### V6: 단정 금지 (유사 사례 라벨 검증)

**통과 조건**: 🟡(유사 사례) 라벨이 붙은 인용에서 단정형 표현이 없다.

**금지 표현 예시**:
- "이 케이스도 X입니다" ❌
- "따라서 귀사도 Y에 해당합니다" ❌
- "동일하게 적용됩니다" ❌

**허용 표현 예시**:
- "유사 사례에서는 X로 해석된 바 있습니다" ✅
- "참고가 될 수 있는 사례입니다" ✅

**실패 시**: 재생성 1회

---

## 최종 출력 형식

```json
{
  "V1": "PASS | FAIL",
  "V2": "PASS | FAIL",
  "V3": "PASS | FAIL",
  "V4": "PASS | FAIL",
  "V5": "PASS | AUTO_ATTACHED",
  "V6": "PASS | FAIL",
  "retry_count": 0,
  "final_status": "PASS | E-VERIFY-FAIL"
}
```

> `final_status: "E-VERIFY-FAIL"` 시 답변을 회계사에 절대 노출하지 말 것.
> 대신 "현재 검색 결과로는 확인이 어렵습니다. 담당 세무사에게 직접 문의하시기 바랍니다." 출력.
