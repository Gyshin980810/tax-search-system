# 문서 동기화 워크플로우 — sync-docs SKILL

## 배경

2026-07-06, TAX-6B-9~37(28개 티켓)이 실제로는 완료돼 있었는데 `ROADMAP.md`·`docs/PRD.md`에
장기간(약 2주) 반영되지 않은 사고가 발견됐다. `ROADMAP.md`는 이제 티켓 완료마다 즉시 갱신하는
것이 원칙(CLAUDE.md §9 9번)이지만, 여러 티켓이 한 번에 밀렸거나 `docs/PRD.md`(새 FR 신설 여부
등 판단이 필요)를 점검해야 할 때는 이 SKILL을 실행해 오늘 검증된 절차를 반복한다.

## 역할

`ROADMAP.md`와 `docs/PRD.md`가 실제 git 이력·리포트와 어긋나 있는지 점검하고, 어긋난 부분만
최소 침습적으로 갱신한다. 코드는 건드리지 않는다(문서 정합 전용).

## 언제 실행하는가

- 회계사가 "문서 최신화해줘" / "PRD·ROADMAP 확인해줘"라고 요청할 때
- `scripts/check-roadmap-sync.js` 훅이 여러 번 경고했는데 아직 처리 안 됐을 때
- 티켓이 5개 이상 누적 완료됐는데 PRD.md 변경이력에 반영이 안 된 것 같을 때

## 절차

### 1단계 — 갭 파악
1. `docs/PRD.md`와 `ROADMAP.md`의 §변경이력(맨 아래 표)에서 **가장 최근 날짜·버전**을 확인한다.
2. `git log --oneline --all --grep="TAX-"` 로 그 날짜 이후의 티켓 커밋을 전부 나열한다.
3. `ls docs/reports/ | sort -V` 로 해당 기간의 리포트 파일 목록을 확인한다.
4. 리포트가 10건 이하면 직접 `Read`로 하나씩 읽는다. 10건을 넘으면 `Explore` 서브에이전트에
   위임해 "티켓별 3~6줄 요약(무엇을·왜·완료상태·회귀테스트 결과)"을 받는다(컨텍스트 절약).

### 2단계 — ROADMAP.md 갱신 (직접 수정, 위임하지 않음)
1. §2에 관련 "별도 트랙" 섹션이 있으면 상태·완료일·검증 결과를 갱신하고, 새 트랙이면
   기존 섹션과 같은 형식(상태·예상 비용·완료 티켓 표·검증·리포트 경로)으로 신설한다.
2. §3 "현재 상태" 표의 해당 행을 갱신하거나 추가한다.
3. §4 "다음 즉시 작업 / 잔여" 목록을 갱신한다(완료 항목 이동, 미착수 항목 명시).
4. §7 변경이력에 새 버전 행을 추가한다(날짜|버전|내용 요약|작성자).
5. 문서 최상단 버전 헤더(작성일 갱신 이력 한 줄)도 함께 갱신한다.

### 3단계 — PRD.md 갱신 판단 (판단 후 위임)
1. 갭에 있는 변경 중 다음에 해당하는 게 있는지 스스로 판단한다:
   - 회계사에게 노출되는 새로운 기능/동작 (→ 새 FR 후보)
   - 기존 FR의 상태(미착수→완료) 또는 범위(규모 확장)가 바뀜
   - 정확성 보증 모델(§6)·검증 규칙(V1~V6)에 영향
2. 내부 버그 수정·재현율 개선(새 기능이 아닌 기존 로직 결함 제거)은 **새 FR을 만들지 않는다**
   — 필요하면 기존 섹션에 한두 줄 각주만 추가.
3. 반영이 필요하면 `prd-writer` 서브에이전트를 **model: opus**로 호출한다. 프롬프트에는:
   - 현재 PRD 버전·최근 변경이력 요약
   - 반영해야 할 사실을 항목별로 구체적으로(티켓 번호·수치·결정 사항 포함)
   - "기존 섹션에 최소 침습적으로 추가/갱신, 새 FR 번호는 현재 최대값+1, 새 섹션 신설 금지"
     같은 스타일 제약
   - 변경이력 서술 방식(날짜|버전|내용|작성자)과 작성자 표기("Claude (prd-writer) + 회계사")

### 4단계 — 검증
1. `git diff --stat ROADMAP.md docs/PRD.md`로 변경 규모가 적절한지(과도한 재작성이 아닌지) 확인.
2. `grep -c "^|"` 등으로 표 구조가 깨지지 않았는지 간단히 점검.
3. 신설한 FR 번호나 티켓 참조가 중복·모순 없는지 `grep`으로 교차 확인.

### 5단계 — 보고
- 무엇을 어디에 반영했는지 요약 보고. **커밋·푸시는 명시적으로 요청받은 경우에만** 진행한다
  (CLAUDE.md 표준 정책 — 자동 커밋 금지).

## 주의사항

- ❌ 코드 파일 수정 금지 (이 SKILL은 `ROADMAP.md`·`docs/PRD.md` 전용)
- ❌ 검색 정확도 지속 개선류(내부 결함 수정)를 새 FR로 과잉 승격 금지
- ❌ PRD.md를 매 티켓 자동 갱신하려고 시도 금지 — 여러 티켓을 모아 판단 후 일괄 처리
- ✅ ROADMAP.md는 이 SKILL 없이도 티켓 완료 시 즉시 직접 갱신하는 것이 원칙(CLAUDE.md §9 9번).
  이 SKILL은 "밀렸을 때 한 번에 안전하게 따라잡는" 용도.
