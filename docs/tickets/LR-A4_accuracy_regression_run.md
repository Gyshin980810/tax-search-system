## 1. Problem (문제 정의)

### 1.1 현재 동작

LR-A1~A3는 답변의 재료·서술·화면을 모두 바꾼다. 그 결과 기존 기대값이 어긋날 수 있으나,
**무엇이 의도된 변화이고 무엇이 결함인지 구분하는 절차가 없다.**

### 1.2 기대 동작

1층 변경 이후의 회귀 상태를 실행·분류해 확정한다. **기대값은 이 티켓에서 바꾸지 않는다.**

## 2. Context (기술적 맥락)

### 2.1 대상 평가셋 (재평가로 정정)

| 파일 | 성격 | 본 티켓에서의 역할 |
|---|---|---|
| `eval/golden_case_first.json` | **E2E**(실제 검색→LLM) — `LR-A0-C` 신규 | **주 회귀 기준선**. 1층 전후 비교의 핵심 |
| `eval/golden_direct.json` (66건) | 직접 주입형 픽스처 | 검증기 자체 회귀. **1층 코드 변경과 무관하게 통과하는 것이 정상** |
| `eval/golden_temporal.json` | 직접 주입형 | 동일 |
| `eval/golden_repealed.json` | 직접 주입형 | 동일 |
| `eval/golden_hallucination.json` | 직접 주입형 | 동일 |

> ⚠️ **구 LR-A4 §2.1의 오기 정정**: `eval/golden_nonlaw_probe.json`·`eval/golden_law_probe.json`은
> 평가셋이 **아니다**. 두 파일의 `description`에 "골든셋 **후보** — 회계사가 본 파일에서 채택"이라
> 명시돼 있고, `tests/` 어디에서도 참조되지 않으며 `scripts/golden/` 생성기 전용이다.
> 회귀 대상에서 제외한다.

### 2.2 두 트랙의 성격 차이 (혼동 금지)

- **직접 주입형**(`golden_direct` 등): `verifier.verify(tc.answer, tc.sourceLaws)`로 완성된 답변을
  주입한다(`tests/golden/run_golden.test.ts:65`). 검색·LLM을 타지 않으므로
  **1층 변경으로 깨진다면 그것은 검증기 계약이 바뀌었다는 뜻**이며 즉시 원인 규명 대상이다.
- **E2E**(`golden_case_first`): 실제 파이프라인을 탄다. 1층 변경이 여기서 드러난다.

착수 시 `eval/GOLDEN_SET_GUIDE.md`와 `eval/README.md`를 먼저 읽고 실행 방법·합격선을 확인한다.

### 2.3 ⚠️ 비용 발생 티켓

E2E 재실행은 **유료 LLM·임베딩 호출**을 발생시킨다.
CLAUDE.md 및 구현 계획서 §0-8에 따라 **실행 전 호출 범위·예상 비용을 산출해 회계사 승인**을 받는다.

## 4. Strategy (구현 힌트)

1. **먼저 무료 게이트** — `npm run lint`, `npm run typecheck`, `npm run test`로 코드 레벨 회귀를 정리한다.
   직접 주입형 골든셋이 여기서 깨지면 **즉시 중단**하고 원인을 규명한다(§2.2).
2. **비용 산출 후 승인** — E2E 케이스 수 × 반복 횟수 × 호출 수 × 단가로 예상 비용을 제출한다.
3. **E2E 실행** — `LR-A0-C` 러너로 1층 **이후** 상태를 측정하고, **이전 기준선과 대조**한다.
4. **회귀 분류** — 차이 항목을 세 갈래로 나눈다.
   - (a) 1층 의도대로 바뀐 것 → `LR-A5`로 이관(회계사 검수 후 기대값 갱신)
   - (b) 의도치 않은 결함 → 원인 티켓(A1·A2·A3)으로 되돌림
   - (c) 판단 보류 → 회계사 질의
5. **`mustNotCite` 위반 별도 집계** — 무관 사례 인용은 정확성 직결이므로 분류와 무관하게 전건 보고한다.
6. **1층 완료 판정 의견** — 게이트 통과 여부와 잔여 위험을 기재한다(성능 판정은 `PERF-LR-001` 결과와 합산).

1. [ ] **AC-1 무료 게이트** — `npm run lint`, `npm run typecheck` 0에러, `npm run test` 전체 GREEN.

       (깨졌다면 검증기 계약 변경이므로 결함으로 분류)
3. [ ] **AC-3 E2E 전후 비교** — `LR-A0-C` 기준선 대비 결과가 항목별로 대조되어 기록된다.
4. [ ] **AC-4 회귀 분류 완료** — 차이 항목이 (a)/(b)/(c)로 **전건** 분류된다.
5. [ ] **AC-5 조문 회귀 0건** — 조문 인용의 라벨·시점·발췌 정확도가 1층 이전 대비 하락하지 않는다.
6. [ ] **AC-6 `mustNotCite` 위반 0건** — 무관 사례 인용이 없다. 1건이라도 있으면 (b) 결함으로 원인 티켓 반송.
7. [ ] **AC-7 기대값 무변경** — 본 티켓 커밋에 `eval/` 기대값 diff가 **없다**.
8. [ ] **AC-8 완료 판정 의견** — 1층 완료 가부 의견과 잔여 위험이 리포트에 기재된다.
