# TAX-6B-9 — 내용(도메인 정확도) 검증기

> 상태: **보류(Deferred)** — 구체 방안은 **Phase 7 완료 후** 결정 (회계사 결정 2026-06-16)
> 선행: TAX-6B-7 (G-5 실측), TAX-6B-8 (골든 회귀 CI)

---

## 배경 — 왜 필요한가

law-verifier V1~V6는 **"거짓말(환각·오인용) 탐지기"**입니다.
즉, 답변이 검색 결과에 없는 조문을 지어냈는지(V1), 발췌가 원문과 글자 단위로
다른지(V2), Tier에 안 맞는 라벨을 썼는지(V3) 등 **인용 무결성**만 봅니다.

그러나 **"인용은 정직하지만 도메인상 틀린"** 유형은 V1~V6가 잡지 못합니다.
G-5 실측에서 두 가지 실제 사례가 드러났습니다.

| 케이스 | 문제 | V1~V6 결과 |
|---|---|---|
| G5-06 | "대체 조항도 존재하지 않습니다" — 사실 오류(실제로는 통합투자세액공제·통합고용세액공제로 분리·흡수) | PASS (거짓말은 아님) |
| G5-10 | 현행 유효한 직접 근거(조특법 제121조의17)를 **검색에서 놓침** → "직접 근거 없음"으로 응답 | PASS (찾은 범위 내에선 정직) |

이 둘은 "거짓말"이 아니라 **사실 오류·검색 누락**이므로, V1~V6로는 FAIL을
표현할 수 없습니다. (그래서 G-5 expectedStatus는 V1~V6 의미로 PASS 통일함.)
이 빈틈을 메우는 **별도 트랙의 내용 검증기**가 본 티켓의 목적입니다.

---

## 결정 보류 사항 (Phase 7 완료 후)

방식 후보는 다음 2가지이며, **어느 것으로 할지는 Phase 7 완료 후 회계사가 결정**합니다.

- **방안 A — 기대 명제 대조(규칙 기반, 결정론적)**
  - 케이스마다 회계사가 `expectedContent: { mustInclude, mustExclude }`를 작성
  - 시스템 답변을 글자 대조 → CONTENT_PASS/FAIL
  - 장점: 항상 같은 결과, API 키 불필요 → 골든 CI에 그대로 편입 가능
  - 단점: 케이스별 기대 키워드 작성 필요, 표현 다양성에 취약
- **방안 B — LLM 판사(judge)**
  - 별도 LLM이 시스템 답변 vs 회계사 정답노트를 사실 대조
  - 장점: 표현 유연성
  - 단점: 비결정성(TAX-6A-11 교훈), 비용·API 키 필요, 골든 CI 부적합

> 현재 잠정 권고: 골든 CI의 결정론·무키 원칙상 **방안 A**가 적합. 단 최종 결정은 보류.

## 범위 밖 (이 티켓에서 하지 않는 것)

- V1~V6 로직·`TIER_ALLOWED_LABELS`·checkV3 값 변경 금지 (§6.4) — 내용 검증기는
  V1~V6와 **완전히 분리된 별도 레이어**로 추가
- G-5 expectedStatus(V1~V6 의미)는 본 티켓과 무관 — 이미 PASS로 통일됨
