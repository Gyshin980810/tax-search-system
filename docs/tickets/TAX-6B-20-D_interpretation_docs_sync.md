## 0. 왜 이 티켓이 필요한가 — 두 개의 "본문 없음" 오기록 정정

이 코퍼스 트랙은 전제가 **두 번 뒤집혔다**(부모 §0). 그 과정에서 여러 문서·메모리에 지금은 **틀린**
기록이 남아 있다. 코드는 20-A~C로 이미 "국세청 해석례 본문을 크롤링으로 확보→벡터 검색"하는데,
문서만 "본문 API 없음 / 목록만"에 머물러 있으면 다음 작업자(AI 포함)가 잘못된 전제로 판단한다.

**정정 대상 오기록:**

| 위치 | 현재(틀린) 서술 | 정정 후 |
|---|---|---|
| TAX-6B-19 티켓·리포트 | "ntsCgmExpc 본문 API 없음" | "공식 API는 존재하나 운영키 권한 봉쇄 → **taxlaw 크롤링으로 본문 확보**" |
| 부모 티켓 TAX-6B-20 §2.1 | "해석례 본문은 수십~수백자 수준" | 방안②(HWP 전문) 실측 평균 1,869자·최대 26,886자로 전제 뒤집힘 — 정정 주석 |
| `nationalTaxLaw.ts:918~921` 주석 | "본문 조회 단계 없이 content=''" | 실시간 어댑터는 여전히 content=''(P95), **오프라인 코퍼스는 벡터 적재됨**을 명시 |
| 메모리 `project_nonlaw_interp_tracks` | (부분적으로 갱신됨) | 20-A~D 완결 상태·크롤링 확정 경위 반영 |

> ⚠️ **주의:** `nationalTaxLaw.ts`의 실시간 어댑터는 **의도적으로 content=''를 유지**한다(P95 보호,
> 부모 §3.2). 여기서 정정하는 것은 "본문을 아예 못 구한다"는 **오해**이지, 실시간 어댑터를 바꾸라는
> 것이 아니다. 본문은 오프라인 코퍼스(20-A~C)로만 확보한다.

> 📌 **정정 방식(역사 보존):** 과거 티켓·리포트(TAX-6B-19·부모 §2.1)는 **본문을 고쳐 쓰지 않는다**
> (당시 결정 경위 보존 — "역사 다시 쓰기" 금지, 원문 보존 철학과 동일 원리). 대신 **문서 상단 인용
> 블록에 날짜 있는 정정 주석을 추가**한다(부모 티켓이 이미 쓰는 방식). 현행 문서(SSOT·PRD·CLAUDE.md·
> 코드 주석·메모리)는 본문을 직접 갱신한다.

## 1. Problem (문제 정의)

### 1.1 현재 동작

- 코드는 국세청 해석례 본문을 크롤링→벡터 적재→의미 검색까지 하는데(20-A~C), **SSOT/PRD/CLAUDE.md·
  일부 티켓·메모리**는 여전히 "본문 API 없음/목록만"에 머물러 있음.
- 문서 위계상 SSOT(헌법)·PRD(사양)에 국세청 해석례 **본문 코퍼스 정책**이 명문화돼 있지 않음
  → 향후 작업자가 "해석례는 목록만"으로 오판할 위험.

### 1.2 기대 동작

- SSOT §7(세법 도메인)·PRD §6(정확성 보증)에 **국세청 해석례 본문 크롤링 확보·벡터 적재·참고 목록
  합류** 정책이 명문화됨.
- 과거 "본문 없음" 기록이 "공식 API 봉쇄 → 크롤링 확보"로 정정되어 문서 간 모순 제거.

### 1.3 영향·중요도

- 기능 변화는 없으나(문서 전용), **다음 작업자의 오판 방지**가 핵심 가치. CLAUDE.md §9 5번(SSOT 우선)·
  §10(문서 동기화 정책)의 재발 방지 취지와 정합.

## 7. Risks / Notes

- ⚠️ **문서만 티켓의 함정**: 코드 로직을 무심코 건드리지 말 것. diff는 `.md`·주석에 한정.
- ⚠️ **오기록 누락**: "본문 없음" 서술이 여러 문서·메모리에 흩어져 있음 → grep 일괄 탐색 필수(정정 누락 시
  다음 작업자 오판 재발).
- ⚠️ **문서 위계**: SSOT > PRD > CLAUDE.md. 하위부터 고치면 모순 → 상위부터 정합(CLAUDE.md §10).
- ℹ️ **ROADMAP 이중 반영 방지**: 20-A~C가 각 완료 커밋에서 이미 §3을 갱신했다면 중복 추가 말고 누락분만 보정.
- ℹ️ **`/sync-docs`**: PRD 신규 FR 판단이 필요하면 스킬로 `prd-writer`(Opus) 위임 가능(CLAUDE.md §10).
- ⚠️ **V1 오매칭 잔여 리스크(2026-07-10 검토, 낮은 확률·문서화만)**: `lawVerifier.ts` `identityOf`(76행)의
  V1 대조는 caseNumber 기반인데, 2004년 이전 해석례 2건 이상이 같은 caseNumber(세목명)로 **한 검색
  결과에 동시에** 잡히는 드문 경우 다른 문서로 오매칭될 수 있다. LLM 인용 텍스트에는 externalId가
  없어 externalId로는 못 고치는 구조(인용 형식 자체의 설계 변경 필요) — 이 티켓에서는 SSOT에 알려진
  한계로 기록만 하고, 실측 빈도가 유의미해지면 별도 티켓으로 승격.
