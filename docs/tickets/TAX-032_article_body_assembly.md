# TAX-032 조문 본문 항·호 조립 — content 완전화 (통증 B)

> 조문 응답에 **이미 들어있는 `항`·`호` 하위노드를 원문 그대로 조립**해, 현재 "조문 제목만"
> 반환되는 본문 누락을 해소한다. **추가 API 호출 0건**(JO 파라미터 불필요 — 진단으로 폐기).
>
> 근거: JO 진단 실측(2026-05-24), `docs/reports/korean-law-mcp_analysis.md`.
> ⚠️ **대원칙: 원문 보존(§6.1)** — 항·호를 조립하되 **문자 단위로 원문과 일치**해야 하며
> 요약·의역·재구성은 절대 금지. 인용 무결성(V2)이 이 티켓의 합격선이다.

## 1. Problem (문제 정의)

### 1.1 현재 동작 (재현 완료)
`src/adapters/nationalTaxLaw.ts:470` — `content`에 `조문내용`만 저장.
```
부가가치세법 제26조 → content 25자: "제26조(재화 또는 용역의 공급에 대한 면세)"  ← 제목만
소득세법   제55조 → content  8자: "제55조(세율)"                              ← 제목만
```
조문에 항·호가 많으면 `조문내용`은 **제목 줄만** 담고 본문은 `항` 하위노드로 빠진다.
현재 어댑터는 `항`을 **읽지 않는다**.

### 1.2 실측 발견 (JO 진단 2026-05-24)
- **`항` 하위노드는 JO 파라미터 없이도 응답에 이미 존재**한다(부가세 2개, 소득세 2개, 지방세 5개).
- ❌ **JO 파라미터는 역효과**: JO를 주면 `항` 노드가 사라져 0자 반환(부가세·소득세 실측). → JO 경로 폐기.
- 따라서 해법은 **전체 묶음 응답의 `항`·`호`를 조립**하는 것(추가 호출 불필요).

### 1.3 기대 동작
`content` = `조문내용`(제목) + 각 `항내용`(+ 각 `호내용`)을 **원문 순서·문자 그대로** 결합.

## 2. Context (기술적 맥락)

### 2.1 실측한 `항` 구조 (법령마다 다름 — 구현 시 정규화 필요)
| 조문 | 항 키 | 특이점 |
|---|---|---|
| 부가세 제26조 | `[항번호, 항내용, 호]` | 항내용=문자열, 호 20개 |
| 소득세 제55조 | `[항번호, 항내용]` | ⚠️ **항내용이 중첩 배열**(세율표): `[["①거주자..."]]` |
| 지방세 제11조 | `[항제개정유형, 항번호, 항내용, 호, 항제개정일자문자열]` | 호 8개, 개정 메타 포함 |

→ **난관 1**: `항내용`이 문자열인 경우와 **배열(표)**인 경우를 모두 원문 보존하며 평탄화.
→ **난관 2**: `호`(하위 `호내용`)도 함께 조립해야 완전한 본문이 된다.
→ **난관 3**: 단일 항/단일 호는 객체, 복수는 배열로 오는 혼재(기존 어댑터의 `Array.isArray` 패턴 재사용).

### 2.2 영향 파일
- `src/adapters/nationalTaxLaw.ts` — `fetchArticles()` 내 `content` 조립부 + `parseArticleHead`.
- `src/domain/TaxLaw.ts` — content는 그대로 string 유지(스키마 변경 불필요 예상).
- 진단 재현: `scripts/diagnostics/jo_probe.mjs`(읽기 전용, 키 미포함).

### 2.3 korean-law-mcp 대비 — 우리가 다르게 하는 점
- korean-law-mcp는 판례 '이유'를 800자+중략+400자로 **축약**한다 → 우리는 §6.1 위반이라 **절대 도입 금지**.
- 우리는 토큰을 더 쓰더라도 **원문 문자 일치**를 택한다(시스템 정체성).

## 3. Scope (작업 범위) ⭐

### 3.1 허용
- [ ] `assembleArticleContent(article)` 헬퍼: `조문내용` + `항[].항내용`(+ `호[].호내용`)을 원문 결합.
      - 항내용이 **배열이면** 원문 텍스트만 순서대로 평탄화(요약·재배열 금지).
      - 항·호 모두 단일/배열 혼재 정규화.
- [ ] `fetchArticles()`가 `content`에 조립 결과 사용(기존 `조문내용` 단독 대체).
- [ ] 단위 테스트: 부가세 제26조(호 다수)·소득세 제55조(표 배열)·지방세 제11조(호 포함)로
      조립 결과가 **원문 문자열을 포함**하고 누락이 없는지(고정 픽스처로 검증).

### 3.2 금지
- ❌ **JO 파라미터 사용**(진단상 역효과 — content 0자).
- ❌ **원문 요약·의역·표 재구성**(§6.1, V2 위반). 축약 절대 금지.
- ❌ 법령 매칭 로직 변경(그건 TAX-031 소관 — 범위 분리).
- ❌ 항·호에 없는 텍스트 보간·정렬 변경(원문 순서 보존).

### 3.3 ⚠️ 사전 검증 필요(구현 1순위)
- 소득세 제55조 `항내용` 중첩 배열의 **정확한 구조**를 먼저 덤프(`jo_probe.mjs` 확장)해
  평탄화 규칙을 확정한 뒤 조립 로직 작성. (추측 금지 — §11)

## 4. Strategy (구현 힌트)
1. 먼저 세율표(소득세 제55조) 항내용 배열의 전체 구조를 진단 덤프로 확정.
2. `assembleArticleContent`: 제목 → 항(번호+내용) → 호(번호+내용) 순, 원문 줄바꿈/기호 보존.
3. 배열형 항내용은 "텍스트 노드만" 추출해 원문 순서대로 join(표 셀 텍스트 손실·재배열 금지).
4. 결합 후 결과가 원문과 문자 단위로 대조 가능한지(V2) 테스트 픽스처로 고정.

## 7. Risks / Notes
- **표 평탄화 손실**: 세율표를 한 줄로 합치면 행·열 의미가 흐려질 수 있음 → 원문 줄바꿈·구분기호 보존이 관건. 손실 의심 시 STOP & ASK.
- **content 비대화**: 항·호 많은 조문은 길어짐 → 토큰↑. 우리는 무결성 우선이라 허용하되, excerpt(발췌)는 회계사가 핵심부로 좁힘(골든셋 워크플로우와 동일).
- **§6.1 위반 유혹**: "길어서 줄이자"는 절대 금지. 줄이려면 발췌(excerpt)로, 원문(content)은 그대로.
