# TAX-016C 조세심판원 결정례(특별행정심판례) 검색 추가

> TAX-016에서 분할된 마지막 자료원. 조세심판원 결정례를 검색 결과에 포함한다.
> **016B와 다른 핵심: 본문(전문)이 제공된다 → 발췌 인용(citable) + law-verifier V검증 대상.**
> 선행: TAX-015B/C/D, TAX-016A, TAX-016B 완료.

## 1. Problem (문제 정의)

### 1.1 현재 동작
- 검색 결과에 법령(T1·T2)·법제처 해석례(T3)·국세청 해석(T3)·판례(T4)는 포함됨.
- 그러나 **조세심판원 결정례(조세 불복 단계의 핵심 판단 근거)**가 빠져 있음.

### 1.2 기대 동작
- 회계사 검색 시 조세심판원 결정례가 검색 결과에 포함된다.
- **본문이 제공되므로** 발췌 인용(인용 카드)으로 노출되고 law-verifier V1~V6를 통과해야 한다(판례·법제처 해석례와 동일 경로).
- 결정번호(사건번호)·생산기관(조세심판원)·결정일·원문 링크를 표기한다.

### 1.3 영향·중요도
- 조세 불복 실무에서 조세심판원 결정례가 자주 인용됨 → 실무 가치 큼.
- 비법령 검색 트랙(판례·해석례)의 마지막 퍼즐로 "조문→해석례→심판례→판례" 판단 순서를 완성.

## 2. Context (기술적 맥락) — 실호출 조사 결과(2026-05-22)

### 2.1 조사로 확정된 사실
- 조세심판원 결정례는 **국가법령정보 공동활용(open.law.go.kr) "특별행정심판" 분류**에 존재 — "조세심판원 특별행정심판례 **목록 조회 + 본문 조회**" 둘 다 제공(국세청 해석과 달리 본문 있음).
- ⚠️ **`decc`는 조세심판원이 아님(정정 2026-05-22).** `target=decc`는 기존 키로 접근되며 정상 데이터를 반환하지만, 이는 **일반 행정심판재결례**(재결청=국민권익위원회·시도 행정심판위 등)다. 세법 쿼리(양도소득세·법인세·가지급금)는 `decc`에서 **0건** → **조세심판원 사건은 decc에 없음**(특별행정심판은 별도 target).
  - decc 응답 필드(참고): `id, 재결청, 처분청, 사건번호, 행정심판례상세링크(⚠️OC 포함), 재결구분코드, 행정심판재결례일련번호, 의결일자, 처분일자, 재결구분명, 사건명`.
- **조세심판원(특별행정심판) target 미확정** — `tt/ttc/taxt/josim/ttSpecial/sptaxt/stax`는 전부 무효(비JSON). 정확한 코드는 회계사 로그인 가이드(016B의 ntsCgmExpc처럼) 또는 data.go.kr 명세에서 확정 필요.
- **폴백 경로:** 공공데이터포털 ID **15140320**(법제처_조세심판원 행정심판 재결례) — 별도 serviceKey 필요.

### 2.2 승인 후 확정 필요(회계사 협조)
- (1) `decc`가 **조세심판원만**인지, **전체 행정심판재결례**(여러 위원회 포함)인지 → 조세심판원만 거르는 **소관기관/처리기관 필터 파라미터** 유무.
- (2) **본문 조회** 방식 — `lawService.do?target=decc&ID=결정일련번호` 형태인지, 응답 본문 필드(주문·이유·청구취지 등) 키.
- (3) 목록 응답 필드(결정번호·사건명·결정일자·생산기관·일련번호·상세링크) 정확한 키.
- (4) 상세링크의 키(OC) 노출 여부 → 노출 시 키 제거 재구성.

### 2.3 아키텍처 힌트
```
NationalTaxLawAdapter
  ├ fetchArticles(law)              [기존]
  ├ searchInterpretations(expc)     [TAX-016A]
  ├ searchNtsInterpretations(ntsCgmExpc) [TAX-016B — 본문 없음]
  ├ searchTribunal(decc)           [본 티켓 — 목록→본문, 발췌 인용 가능]
  └ searchPrecedents(prec)         [TAX-015]
  → 병합: 법령(T1·T2) → 해석례(T3) → 심판례(T3) → 판례(T4)
```
- 판례(`searchPrecedents`)의 "목록→본문 2단계" 구조를 그대로 본떠 `searchTribunal` 작성.
- `sourceType='심판례'`(도메인 union에 이미 존재), `dateLabel('심판례')='결정일'`(AnswerCard에 이미 구현) → UI 추가 작업 최소.

## 4. Strategy
1. 회계사가 공동활용 "특별행정심판(조세심판원 특별행정심판례)" 카테고리 활용신청 → 승인(1~2일).
2. 승인 후 `decc` 목록(+조세심판원 필터)·본문 실호출 확정, 응답 샘플 리포트 첨부.
3. 판례 어댑터 패턴 복제: 목록 조회 → 본문 조회 → `toTribunalTaxLaw`(sourceType='심판례', T3).
4. `search()` 병합에 심판례 추가(법령→해석례→심판례→판례), 부분 실패 허용.
5. 본문 있으므로 generateAnswer의 citable로 흐름 → V1~V6 검증 통과 확인. lawVerifier V1 식별자(결정번호) 매핑 확인.
