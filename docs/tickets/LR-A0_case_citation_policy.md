## 1. Problem (문제 정의)

### 1.1 현재 상태 — 세 갈래로 갈린다

LR-A1은 벡터 코퍼스(판례·심판례·해석례 약 28만 건)의 사례를 `LabeledAnswer.citations`로
승격하려 한다. 그런데 상위 문서를 **정확히 읽으면** 자료 유형별로 상태가 다르다.

| 자료 | 현재 정책 | 근거 |
|---|---|---|
| **직접검색 비법령(본문 有)** | ✅ 이미 citation 가능 | `generateAnswer.ts:98~109` `splitResults`가 `content` 유무만 보고 `citable`에 넣음. V1도 `caseNumber`로 대조(`lawVerifier.ts:64~75`, SSOT §7.4 V1) |
| **해석례 벡터 코퍼스** | ❌ **명문 금지** | `SSOT.md:286` §7.2-a — "**트랙**: 참고 목록(`references`) 전용 — V1~V6 비대상·**발췌 인용 승격 금지**" |
| **판례·심판례 벡터 코퍼스** | ⚠️ **명문 공백** | SSOT·PRD에 금지 조문 없음. 코드 주석(`generateAnswer.ts:276~277`)에만 "승격되지 않는다"는 설명이 있음 |

### 1.2 흔한 오독 — "비법령은 citation 불가"가 아니다

`SSOT.md:320` / `PRD.md:444`의 문장은 다음과 같다.

> 본문(발췌)이 없는 비법령 자료 **및 인용되지 않은 본문 있는 비법령 자료**는 발췌 없이
> 관련도순 상위 N건으로 노출하는 **참고 목록**으로만 제시한다.
> 참고 목록은 발췌가 없으므로 **V1~V6 검증 대상이 아니며, 어떤 경우에도 citation으로 승격할 수 없다.**

이 규칙이 금지하는 것은 「**참고 목록에 이미 들어간 항목**을 인용으로 끌어올리는 행위」다.
「본문이 있고 인용된 비법령이 citation이 되는 것」은 금지 대상이 아니며 현행 코드가 이미 그렇게 동작한다.

따라서 본 티켓이 결정해야 하는 것은 **"비법령을 인용할 수 있는가"가 아니라
"벡터 코퍼스에서 온 자료를 인용 후보로 삼을 수 있는가"** 이다.

### 1.3 왜 문서 개정이 먼저인가

- 해석례는 **명문 금지**라 코드부터 고치면 SSOT 위반이 된다(CLAUDE.md §9-5 SSOT 우선).
- 판례·심판례는 명문 공백이라 지금 정하지 않으면, 구현 후 "그때 정한 적 없다"는 분쟁이 남는다.
- 승격 조건·검증 범위·실패 시 기권 정책을 먼저 못 박아야 **감사 가능한 경로**가 된다.

| `src/adapters/lawVerifier.ts:64~75` | V1 비법령 `caseNumber` 대조 |

### 2.2 V1~V6가 검증하지 **않는** 것 (결정의 핵심 근거)

`lawVerifier.ts` 전체를 확인한 결과, V1~V6 어디에도 다음을 보는 항목이 없다.

- 인용된 사례가 **질문과 법적으로 관련 있는가**
- 사례의 **결론(인용/기각·과세/비과세)을 올바르게 이해했는가**
- 사례의 **사실관계가 질문 사안과 유사한가**

V1은 존재 여부, V2는 글자 일치만 본다. 즉 **"원문은 완벽히 정확한데 사안이 전혀 다른 사례"**는
현행 검증 전 단계를 통과한다. 벡터 유사도(cosine ≥ 0.5)와 건수 상한만으로 인용을 강제하면
이 유형이 답변 중심에 놓인다 — 회계사가 가장 속기 쉬운 형태다.

## 4. 회계사 결정 항목

### D-1. 인용 후보로 삼을 자료 범위

| 선택지 | 장점 | 단점 |
|---|---|---|
| **①(추천) 판례·심판례만 허용, 해석례는 참고 목록 유지** | 명문 위반이 없는 영역부터 연다. SSOT §7.2-a를 건드리지 않아 개정 범위가 최소. 판례·심판례는 결론·판단 기준이 원문에 명시돼 발췌 인용에 적합 | 국세청 해석례(13.5만 건, 실무 활용도 높음)가 계속 참고 목록에만 남는다 |
| ② 판례·심판례·해석례 전부 허용 | 벡터 코퍼스 28만 건 전부가 답변 논리에 참여. 체감 개선이 가장 큼 | SSOT §7.2-a 명문 개정 필요. 해석례는 크롤링 확보 본문이라 원문 정합성 리스크가 판례보다 높다 |
| ③ 전부 유지(승격 없음) | 변경 0, 가장 안전 | 사례 중심 전환 자체가 성립하지 않음 |

### D-2. 승격 조건 (인용 적격 게이트)

| 선택지 | 장점 | 단점 |
|---|---|---|
| **①(추천) 유사도 + 본문 존재 + 질문 용어 교차 확인** | 벡터 유사도 단독보다 무관 사례를 크게 줄인다. 결정론적이라 테스트로 고정 가능 | 교차 확인 기준을 새로 설계해야 하고, 적격 0건이 늘어 기권이 잦아질 수 있다 |
| ② 유사도 임계값만 상향(예: 0.5 → 0.65) | 구현이 가장 단순 | 임계값은 노이즈(0.42)와 진짜 이득(0.38)이 역전한 실측이 있어(`generateAnswer.ts:64~65`) 단독 분리가 불가능함이 이미 확인됨 |
| ③ 2층 관계 검증 통과 사례만 | 정확성 최상 | 2층 완료 전까지 1층이 멈춘다 |

### D-3. 적격 사례가 0건일 때 (기권 정책)

| 선택지 | 장점 | 단점 |
|---|---|---|
| **①(추천) 기권 — 사례 인용 없이 조문 중심 답변 + "관련 사례를 확인하지 못했습니다" 명시** | "틀린 답은 없는 답보다 나쁘다"(CLAUDE.md §2)에 부합. 무관 사례 강제 인용을 구조적으로 차단 | 사례를 기대한 질문에서 화면이 허전할 수 있다 |
| ② 유사도 상위 N건을 무조건 인용 | 항상 사례가 보인다 | 무관 사례가 답변 중심에 놓인다(§2.2). **권하지 않음** |

### D-4. 검증 범위 — 승격된 사례에 무엇을 적용하는가

| 항목 | 제안 |
|---|---|
| V1 출처 존재 | 적용 (`caseNumber` 대조) |
| V2 인용 무결성 | **적용 — 면제 아님**. 벡터 코퍼스는 `content != ''`이므로 문자 단위 대조 가능(`vectorSearch.ts:74`) |
| V3 라벨 | 적용. T3·T4 → 🟡·⚪·⚫ 상한 유지(🟢 승격 금지) |
| V4 시점 | 적용. `[결정: YYYY.MM.DD]` |
| V5 면책 | 적용 |
| V6 단정 금지 | 적용 |
| **관련성·결론 정합** | ❌ **현행 V1~V6로 검증 불가** — 별도 트랙(LR-A0-C 평가 계약 + 2층)으로 관리 |

> D-4는 사실 확인 성격이라 선택지가 아니라 **확인 요청**이다. 이견이 없으면 위 표대로 확정한다.
