## 1. Problem (문제 정의)

### 1.1 현재 동작

LR-A2까지 완료되면 답변 **내용**은 사례 중심으로 바뀌지만, `AnswerCard`의 화면 배치는
여전히 조문 인용을 상단에 크게 두고 사례는 하단 참고 목록에 두는 구조다.
내용과 화면이 어긋나 회계사가 답변을 읽는 동선이 끊긴다.

### 1.2 기대 동작

```
[답변]
■ (사례 섹션 — 제목은 §8.1 승인 항목)
  🟡 대법원 2019두44095 [결정: 2020.01.30]
     "(…) 원문 발췌 (…)"
  🟡 조심2012서2892 [결정: 2013.05.21]
     "(…) 원문 발췌 (…)"
  ⓘ 사실관계 차이에 따라 적용 결과가 달라질 수 있습니다

■ 적용 법령 (근거)
  🟢 법인세법 제25조 [현행]
     "(…) 원문 발췌 (…)"

■ 참고 자료 (인용되지 않은 검색 결과)

[하단] 면책 고지
```

- 사례 섹션이 상단, 조문은 "적용 법령" 섹션으로 하단
- 각 항목에 원문 링크·결정일·Trust Tier·라벨 유지
- 면책 고지는 기존 위치·형식 유지(V5)

### 1.2-b ⚠️ 제목이 만드는 오해 (재평가 신설)

기존안 "**이 쟁점의 판단 기준**"은 두 가지 문제가 있다.

1. **🟡 유사사례를 적용 기준처럼 읽히게 한다.** "판단 기준"은 그 사안에 적용될 규범처럼 들리지만,
   실제로는 다른 사실관계에서 나온 참고 자료다. 라벨 체계(🟡=단정 금지)와 제목이 어긋난다.
2. **해석례가 빠져 있다.** 부제 "(판례·심판원)"은 LR-A1이 다루는 세 유형 중 해석례를 누락한다.

제목안은 §8.1 승인 항목으로 제시한다.

### 1.3 영향·중요도

1층의 마무리. 회계사가 실제로 보는 화면이 이 티켓에서 완성된다.

## 4. Strategy (구현 힌트)

1. **`citations`를 `sourceType` 기준으로 사례군(판례·심판례·해석례)과 법령군으로 나눈다.**
   동시에 각 항목의 `trustTier`가 예상 범위(사례=T3·T4, 법령=T1·T2)와 **일치하는지 검증**한다.
   어긋나는 항목이 있으면 조용히 배치하지 말고 드러낸다(§7 위험 4).
2. 사례군을 먼저, 법령군을 "적용 법령" 섹션으로 뒤에 렌더링한다.
3. **그룹 내부 정렬을 결정론적으로 고정한다** — 배열 순서 그대로 둘지, 결정일 역순 등으로 정렬할지
   §8.1에서 확정하고 테스트로 못 박는다.
4. 각 군이 비어 있으면 해당 섹션 헤더를 그리지 않는다(빈 섹션 방지).
5. 사례 섹션에 **"사실관계 차이에 따라 적용 결과가 달라질 수 있습니다"** 안내를 둔다.
6. 기존 참고 목록 렌더링은 그대로 유지하고 위치만 조문 아래로 둔다.
7. **혼합 시점 처리** — 카드 상단의 단일 `answer.temporalLabel`은 조문 `[현행]`과 사례 `[결정:…]`이
   섞이면 의미가 모호해진다. 각 citation의 개별 시점 라벨은 그대로 유지하고, 상단 라벨의
   의미를 제한하거나 표시 방식을 §8.1에서 확정한다.

## 5. Acceptance Criteria (완료 조건)

1. [ ] **AC-1 순서** — 사례 인용이 조문 인용보다 위에 표시된다.
2. [ ] **AC-2 빈 섹션 없음** — 사례가 0건이면 사례 섹션 헤더가 렌더링되지 않는다(조문도 동일).
3. [ ] **AC-3 표시 요소 유지** — 모든 인용에 라벨·시점 라벨·원문 링크가 표시된다.
4. [ ] **AC-4 면책 유지** — 면책 고지가 기존 위치·문구로 표시된다.
5. [ ] **AC-5 참고 목록 유지** — 참고 목록에 발췌가 추가되지 않는다.
6. [ ] **AC-6 관계·결론 문구 없음** — 섹션 제목·그룹 헤더에 "반대 법리"·"같은 결론"류 표현이 없다.
7. [ ] **AC-7 해석례 포함** — 사례 섹션이 판례·심판례·해석례 세 유형을 모두 수용한다
       (`LR-A0` D-1에서 허용된 범위 기준).
8. [ ] **AC-8 Tier 정합** — `sourceType`과 `trustTier`가 어긋나는 항목이 조용히 잘못 배치되지 않는다.
9. [ ] **AC-9 정렬 결정론** — 같은 입력에 대해 항상 같은 순서로 렌더링된다(테스트로 고정).
10. [ ] **AC-10 사실관계 안내** — 사례 섹션에 적용 한계 안내가 표시된다.
11. [ ] **AC-11 기계 게이트** — `npm run lint`, `npm run typecheck` 0에러, `npm run test` 전체 GREEN,
        `npm run test:e2e`(또는 승인된 대상 테스트) 통과.

## 6. Verification (검증 단계)

1. `npm run lint` / `npm run typecheck` → 0에러
2. `npm run test` → 전체 GREEN
3. `npm run test:e2e` → 답변 카드 관련 시나리오 통과
4. `npm run dev` → 사례형 질문 실행 → 사례 섹션이 상단에 오는지 육안 확인
5. 조문형 질문 실행 → 사례 섹션 없이 "적용 법령"만 정상 표시되는지 확인(AC-2)
6. 혼합 시점 답변(조문 `[현행]` + 사례 `[결정:…]`) 육안 확인 → 상단 라벨이 오해를 주지 않는지
7. 모바일 폭(좁은 화면)에서 레이아웃이 깨지지 않는지 확인
8. 원문 링크 클릭 → 국세법령정보시스템·판례 원문으로 이동 확인
9. 회계사 육안 검수: 섹션 제목이 🟡 자료를 "적용 기준"으로 오해하게 하지 않는지
