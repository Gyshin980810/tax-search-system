# TAX-031 법령 매칭 정확도 — 정확매칭 + 세법 약칭 사전 (통증 A)

> 검색 결과 후보 중 **시드/쿼리 법령명과 정확히 일치하는 법령을 우선 선택**하고,
> 회계사가 자주 쓰는 **세법 약칭을 풀네임으로 확장**해 동음이의 법령 오매칭을 차단한다.
>
> 근거: korean-law-mcp 분석(`docs/reports/korean-law-mcp_analysis.md`) + JO 진단 실측.
> ⚠️ 본 개선은 **검색[2] 단계 품질 향상**이며, 검증[4]·정답확정(회계사)은 건드리지 않는다.

## 1. Problem (문제 정의)

### 1.1 현재 동작 (재현 완료)
`src/adapters/nationalTaxLaw.ts:450`
```ts
const topLaw = laws[0]   // 검색 후보 5개를 받아놓고 무조건 1번째만 사용
```
검색 API 랭킹 1위를 무조건 채택한다. **법령명 정확매칭·재정렬 로직이 없다.**

### 1.2 실측 재현 (JO 진단 2026-05-24)
"지방세법" 검색 결과:
```
[0] 지방교부세법  (법률)   ← 현재 어댑터가 가져오는 것 (오답)
[3] 지방세법      (법률)   ← 정확매칭이 찾아내는 것 (정답)
```
→ 현재 어댑터는 "지방세법" 질문에 **지방교부세법**을 근거로 답하게 된다(silent 오매칭).
이미 `scripts/golden/buildCases.ts`의 "법령 불일치 경고"가 이 사고를 사후 검출하나, **검색 단계에서 막는 것이 정공법**이다.

### 1.3 기대 동작
- 검색 후보 N개 중 **법령명 완전일치 > 접두일치 > 부분일치** 순으로 선택.
- 회계사 약칭(조특법·국기법·상증세법 등) → **풀네임 확장 후 검색**.

## 2. Context (기술적 맥락)

### 2.1 실측 근거 (이 한 줄이면 통증 A 해결됨 — 진단 확인)
```ts
const chosen = laws.find((l) => l.법령명한글 === keyword) ?? laws[0]
```
"지방세법" 진단에서 이 로직이 `[3] 지방세법`을 정확히 선택함을 확인했다.

### 2.2 재사용/영향 파일
- `src/adapters/nationalTaxLaw.ts` — `fetchArticles()`의 `laws[0]` 선택부(`searchLaws` 직후).
- (신규) `src/domain/lawAliases.ts` — 세법 약칭 사전(닫힌 집합) + 정규화 함수.

### 2.3 korean-law-mcp 대응 기법
- `LAW_ALIAS_ENTRIES`(52+) → 약칭 자동 확장.
- `scoreLawRelevance()` → 문맥 점수 동음이의 구분. (우리는 1차로 정확매칭으로 충분, 점수화는 후순위.)

## 3. Scope (작업 범위) ⭐

### 3.1 허용
- [ ] `src/domain/lawAliases.ts` 신규: 세법 약칭 사전 + `normalizeLawName(keyword)` 함수.
      - 초기 엔트리(닫힌 집합, 회계사 확정): 조특법→조세특례제한법, 국기법→국세기본법,
        부가세법→부가가치세법, 상증세법/상증법→상속세 및 증여세법, 종부세법→종합부동산세법,
        법인세법/소득세법/지방세법 등 풀네임은 그대로.
- [ ] `fetchArticles()`에 **정확매칭 우선 선택** 로직(`완전일치 > 접두 > 부분 > [0]`).
- [ ] 선택 결과에 **매칭 근거**(완전/접두/부분/폴백)를 내부 로깅(식별자 미포함, §7).
- [ ] 단위 테스트: "지방세법"→지방세법, 약칭 확장, 폴백 케이스.

### 3.2 금지
- ❌ 법령 원문 변형 (§6.1) — 본 티켓은 "선택"만, 본문 가공은 TAX-032 소관.
- ❌ 검증[4]·law-verifier 수정 (검색 품질 개선이지 검증 변경 아님).
- ❌ 약칭을 사용자 노출 기능(FR)으로 승격 — 그건 PRD/SSOT 정합 별도 티켓(STOP & ASK).
- ❌ 티켓 범위 밖 파일 수정(예: 조문 본문 조립은 TAX-032).

## 4. Strategy (구현 힌트)
1. `normalizeLawName(keyword)`로 약칭→풀네임 정규화 후 `searchLaws(query)` 호출.
2. 후보에서 `법령명한글 === normalized`(완전) → `startsWith`(접두) → `includes`(부분) → `laws[0]`(폴백) 순 선택.
3. "지방세법"이 "지방세법 시행령"보다 우선되도록 **완전일치가 접두일치를 이긴다**는 순서 보장.
4. 약칭 사전은 도메인 지식이므로 `src/domain/`에 상수로 두고 어댑터가 참조(계층 정합).

## 7. Risks / Notes
- **재정렬 부작용**: 완전일치가 의도와 다른 동명 조문을 고를 위험 → 골든셋 회귀가 안전망.

- **정합**: 약칭을 UI 노출 기능으로 승격 시 PRD FR 신설 필요(임의 FR 금지).
