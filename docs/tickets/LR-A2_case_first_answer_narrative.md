## 1. Problem (문제 정의)

### 1.1 현재 동작

LR-A1 완료 시점에는 사례(판례·심판례·해석례) 본문이 LLM 컨텍스트에 들어오지만,
`SYSTEM_PROMPT`는 여전히 **조문 중심 서술**을 지시한다. 따라서 사례가 재료로 있어도
답변은 "조문은 이렇다 + 참고로 판례가 있다" 형태에 머문다.

회계사가 실제로 원하는 것은 반대다.

> "이 쟁점에서 법원·심판원은 어떤 기준으로 판단했는가, 그리고 결론이 갈린 사례는 무엇인가"

### 1.2 기대 동작

답변 본문의 서술 순서를 다음과 같이 바꾼다.

```
■ 판단 요소 (판례·심판원·해석례에서 확인되는 것)   ← 주인공
   🟡 사례 A — 판단 기준 발췌
   🟡 사례 B — 다른 판단이 이루어진 사례
■ 적용 법령 (근거)                                ← 근거로 하강
   🟢 조문 [현행]
■ 면책 고지
```

- 사례가 먼저, 조문이 그 근거로 뒤따른다.
- 결론이 갈리는 사례가 있으면 **나란히 제시**한다(그룹핑·관계 명명 없이).
- 🟡 자료로 단정하지 않는다(V6 유지).

### 1.3 영향·중요도

1층의 **체감 변화가 실제로 발생하는 티켓**이다. A1은 재료 투입, A3는 화면 배치이며,
답변 내용 자체가 바뀌는 것은 이 티켓이다.

### 2.2 ⚠️ SYSTEM_PROMPT는 누적 자산이다 (최우선 주의사항)

현재 `SYSTEM_PROMPT`는 여러 티켓이 쌓아 올린 결과물이며, **블록을 지우면 과거 결함이 되살아난다.**

| 블록 | 출처 티켓 | 지우면 재발하는 문제 |
|---|---|---|
| 라벨링 규칙(Tier 자동 계산 안내) | TAX-042D → TAX-6B-28 | V3 LABEL_MISMATCH 재발 |
| 시점 라벨 결정 트리(1~3순위) + 금지 예시 | TAX-050 | V4 시점 라벨 누락 재발 |
| T1·T2 부재 시 동작 규칙 | TAX-048 | 직접 근거 부재 고지 누락 |
| 질문 전제 검증 규칙 | TAX-6A-8 | 거짓 전제 질문에 그대로 답하는 문제 재발 |
| 중략 마커 처리 규칙 | TAX-042F | 잘린 본문을 인용해 V2 실패 |
| 단정 금지 표현 규칙 | CLAUDE.md §6.3 | V6 위반 |

**원칙: 위 6개 안전 블록은 삭제·축약하지 않는다.** AC-7에서 존재를 기계적으로 고정한다.

### 2.2-b ⚠️ "추가만" 원칙의 예외 — 지정 3개 문구 (재평가 신설)

현행 프롬프트에는 사례 중심 서술과 **논리적으로 충돌하는** 지시가 있다.

| 위치 | 현행 문구 | 문제 |
|---|---|---|
| `llmAnswerGenerator.ts:48` | "아래 제공된 **법령 조문만**을 근거로 답변을 생성합니다" | 사례를 근거로 쓰라는 지침과 정면 충돌 |
| `llmAnswerGenerator.ts:62` | 선정 우선순위 "(1) **T1·T2 출처** > (2) 질문 키워드 매칭 > …" | 5건 상한에서 법령이 먼저 채워 사례가 밀림 |
| userPrompt 섹션명 | "[제공된 법령 조문]" | 사례가 들어오는데 이름이 법령 전용 |

여기에 지침을 **추가만** 하면 "법령만 쓰라"와 "사례를 앞세우라"가 동시에 존재하는
모순된 프롬프트가 된다. 따라서 **이 3개 문구에 한해 최소 수정을 허용**한다.

- "법령 조문만" → 제공된 검색 근거 전체를 포괄하는 표현
- 섹션명 → 자료유형을 포괄하는 명칭
- 선정 우선순위 → 법령과 적격 사례가 함께 선정될 수 있는 규칙

**허용 범위는 위 3개뿐이며, §2.2의 6개 안전 블록은 여전히 불변이다.**
수정 시 각 문구의 출처 티켓 리포트를 먼저 읽고 변경 사유를 본 티켓 리포트에 기록한다.

### 2.3 라벨·검증 제약 (변경 불가)

- `TIER_ALLOWED_LABELS`(`src/adapters/lawVerifier.ts:16`) — T3·T4는 🟡·⚪·⚫만 허용

## 4. Strategy (구현 힌트)

1. **서술 순서 지침 추가** — "판단 요소(사례) → 적용 법령(조문) → 면책" 순서를 명시한다.
   조문 인용을 없애는 것이 아니라 **위치를 뒤로 옮기는 것**임을 분명히 한다.
2. **충돌 문구 최소 수정** — §2.2-b의 3개를 고친다. 나머지는 손대지 않는다.
3. **결론 표시는 원문 연결 시에만** — 사례의 결론을 보여줄 때는 그 결론이 **인용된 발췌 안에서
   확인되는 경우로 한정**한다. 발췌 밖의 결론을 LLM이 요약해 붙이지 않는다.
   - ✅ "A 사건 발췌: '(…) 접대비에 해당한다고 봄이 상당하다'"
   - ❌ "A는 접대비, B는 광고선전비로 결론이 갈립니다"(발췌 밖 요약)
   - ❌ "B는 A와 반대되는 법리입니다"(관계 단정 — 2층 범위)
   - ❌ "따라서 귀사의 경우도 광고선전비입니다"(V6 단정)
4. **직접 근거가 없을 때** — 조문 직접 근거가 없으면 기존 정책대로 "직접 근거를 찾지 못했습니다"를
   명시하고 사례를 라벨링해 제시한다(`tests/unit/noDirectBasisDisclosure.test.ts` 회귀 확인).
5. **사례가 없을 때** — 적격 사례가 0건이면 기존 조문 중심 서술로 자연스럽게 되돌아가야 한다
   (빈 "판단 요소" 섹션을 만들지 않는다).
6. **스모크 회귀를 병합 전에** — 프롬프트 변경 후 회귀 통과는 상위 문서상 필수다.
   `LR-A0-C` 평가셋의 승인된 부분집합(스모크셋)을 **A2 병합 전에** 실행한다(§6-4).

8. 회계사 육안 검수: 결론이 갈린 사례가 있을 때 어느 한쪽으로 단정하거나 묶지 않는지 확인
