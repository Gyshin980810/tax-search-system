# TAX-6B-35 판례 주간 증분 수집 (참조법령 JO 필터 방식)

## Metadata

- **Type**: FEAT
- **Severity**: minor
- **Layer**: infra (scripts)
- **Milestone**: Post-M6B 운영 유지보수 (TAX-6B-34와 짝)
- **Estimated Size**: M (신규 수집 스크립트 1개 + package.json 스크립트 1줄)

---

## 1. Problem

- 기존 판례 10,075건은 외부 저장소 precedent-kr의 **정적 스냅샷**에서 왔다. 저장소가
  실시간 갱신되지 않음을 확인(회계사, 2026-07-04) — git pull 재실행으로는 신규 판례를
  가져올 수 없다.
- 자체 API(`target=prec`)로 수집기를 새로 만들어야 하는데, 전체 판례 169,505건 중
  `사건종류명='세무'`는 약 2%뿐이라 분류 필드만으로 거르면 효율이 낮고,
  **형식은 민사·일반행정이지만 실질은 세금 사건인 판례**(조세 환급 부당이득금 청구 등)를 놓친다.

## 2. 채택 방식: 참조조문(JO) 필터 (회계사 제안, 2026-07-04)

> "참고조문에 법인세법, 소득세법, 부가가치세법 같이 세법들을 참고조문으로 삼는 판례들을
> 모으다보면 세법 관련 판례들을 모을 수 있지 않을까"

**실측 확인(2026-07-04, 프로브 3회):**

| 확인 항목 | 결과 |
|---|---|
| `lawSearch.do?target=prec&JO=법인세법` | totalCnt **1,521건**으로 필터링됨 (엉터리 법령명 → 0건, 실제 필터 확인) |
| 사건종류 교차 포착 | `2025다210837 민사 부당이득금`이 법인세법 참조로 걸림 — 분류 필터로는 못 잡는 실질 세금 사건 포착 |
| `sort=ddes` (최신순) | 정상 동작 (최신 선고일자 2026.04.30까지 확인) |
| 시행령 | `JO=법인세법 시행령` 1,059건 — 시행령 참조도 별도 필터 가능 |
| 본문 검색 대조군 | `search=2&query=법인세법`은 14,890건 — 단순 언급까지 걸려 과다, JO가 정밀 |

**주요 세법별 건수(법률 기준, 2026-07-04):** 법인세법 1,521 / 소득세법 2,288 / 부가가치세법 1,107 /
국세기본법 1,722 / 국세징수법 481 / 상속세및증여세법 1,125 / 조세특례제한법 557 /
지방세법 1,843 / 관세법 621 / 종합부동산세법 30 (교집합 있음 — 합집합은 이보다 작음)

## 3. 기대 동작

```
npm run collect:precedent -- --incremental
  → 세법 목록(SETTLED_TAX_LAWS 배열)을 순회하며 JO별로 sort=ddes 최신 페이지부터 조회.
  → 판례일련번호 기준으로 세법 간 교차 중복 제거.
  → DB(taxlaw_embeddings, source_type='판례')의 case_number와 대조해
    한 페이지 전체가 이미 알려진 경우 해당 JO 페이징 중단.
  → 신규 건만 본문 조회(법원 출처만) 후 scripts/precedent_incremental_<YYYYMMDD>.json 기록.

npm run embed -- --input scripts/precedent_incremental_<YYYYMMDD>.json
  → 기존 embed.ts 그대로 재사용.
```

- **첫 실행은 자동으로 백필(backfill) 역할**: precedent-kr 스냅샷에 없는 판례
  (스냅샷 단절 시점 이후 신규 + 민사·행정 형식의 실질 세금 사건)가 전부 신규로 잡힌다.
  이후 매주 실행은 소량 증분만 잡힌다 — 별도 `--all` 모드 불필요.

## 4. 구현 계획

**영향 파일**: `scripts/collectPrecedent.ts` (신규), `package.json` (`collect:precedent` 스크립트 추가),
`tests/unit/collectPrecedent.test.ts` (신규 — 순수 함수 테스트). 기존 파일 무변경.

1. `collectTribunal.ts` 구조 미러링: listUrl/페이징/재시도/체크포인트/§7 키 비노출(`scrubOc`) 재사용 패턴.
2. `JO` 순회: 세법 목록 상수 배열(법률+시행령 쌍). JO별 독립 페이징 + 전역 `판례일련번호` Set으로 교차 중복 제거.
3. **DB 대조는 case_number 정규화 후 비교**: API 사건번호 표기가 이원적
   (`2025두36013` vs `대법원-2025-두-34754`)이고 precedent-kr 적재분 표기와 다를 수 있어,
   하이픈·법원명 접두 제거 정규화 함수를 만들어 비교(순수 함수 + 테스트).
   content_hash 대조는 불가 — 같은 사건도 precedent-kr 본문(주문 포함 완전판)과
   API 본문(판시사항+판결요지)이 달라 hash가 다름.
4. 본문 수집: `데이터출처명 !== '국세법령정보시스템'`(법원 출처)만 본문 API 호출
   (기존 `nationalTaxLaw.ts`의 `fetchPrecedentBody` 로직과 동일 — 판시사항+판결요지, §6.1 문자 단위 보존).
   국세법령정보시스템 출처는 본문 미제공이라 적재 대상 제외(목록에만 존재).
5. TaxLaw 매핑: sourceType='판례', trustTier='T4', sourceUrl은 키 없는 공개 뷰어 링크.
6. `npm run embed`는 변경 없음.

## 5. Acceptance Criteria

1. [ ] JO 필터로 세법 관련 판례만 수집되고, 사건종류명이 민사·행정이어도 세법 참조 시 포착된다.
2. [ ] DB에 이미 있는 판례(정규화된 case_number 기준)는 본문 재조회·재기록하지 않는다.
3. [ ] 산출물이 기존 `embed.ts` 입력 포맷과 100% 호환된다.
4. [ ] 키(OC) 비노출·§6.1 문자 단위 보존 회귀 없음.
5. [ ] vitest 전체 그린.

## 6. Risks

- **case_number 표기 이원성**: 정규화가 불충분하면 같은 사건이 중복 적재될 수 있음
  (content_hash 안전망이 여기선 작동 안 함). → 정규화 함수 테스트로 방어, 첫 실행 후 중복 검사 쿼리로 확인.
- **세법 목록 누락**: JO 목록에 없는 세법만 참조하는 판례는 못 잡음 → 목록은 상수 배열이라
  추후 한 줄 추가로 확장 가능.
- 첫 실행(백필)의 신규 건수가 수천 건일 수 있음 → 임베딩 비용은 수동 실행 흐름상
  회계사가 건수 확인 후 지출(TAX-6B-34 결정과 동일).

## 7. 확정 결정 (회계사, 2026-07-04)

- **JO 목록 = 국세 8법 + 지방세 3법, 각 시행령 자동 포함(총 22개 질의)**
  - 국세: 국세기본법·국세징수법·법인세법·소득세법·부가가치세법·상속세및증여세법·조세특례제한법·종합부동산세법
  - 지방세: 지방세법·지방세기본법·지방세특례제한법
  - 관세·개별소비세 등 기타 세목은 제외(추후 `TAX_LAW_JO_BASE` 배열 한 줄 추가로 확장 가능)

## 8. 후속 보강 — 사건명 세무 그물 병행 (회계사 결정, 2026-07-04)

**배경(실측):** JO 전체 재수집(`--all`) 8,772건과 DB 판례 9,978건을 대조하니 JO가
**2,552건을 커버하지 못함.** 원인 규명:

| 원인 | 건수(대략) | 성격 |
|---|---|---|
| 제외 세목만 참조(관세·개별소비세·주세·증권거래세) | ~344 | 의도적 제외(정상) |
| **참조조문 공란 하급심** | ~2,200 | JO 사각지대 |

- 못 잡은 2,552건의 **심급 분포: 고법 1,604 · 지법 724 · 대법원 185** → **91%가 하급심**.
- 표본(2024누39327 등 5건) 실측: law.go.kr **참조조문 필드가 통째로 공란**이고 사건종류='세무'.
  JO 필터는 참조조문 메타데이터에 의존하므로 참조조문이 없으면 어떤 JO로도 못 잡는다.
- **이 API에는 사건종류 필터 파라미터가 없음**(nw·prncCtNm·사건종류 등 전부 무시). 대신
  `search=1`(사건명 검색)은 정상 동작하고, 못 잡은 하급심들이 사건명 검색 시 사건종류='세무'로 잡힌다.

**채택:** 기존 JO 그물(Pass A)에 **사건명 세목 키워드 그물(Pass B)** 병행.
- Pass B = `search=1` + 세목 키워드(`TAX_ITEM_NAME_QUERIES`, JO 11법 대응·제외 세목 없음) →
  결과를 **사건종류='세무'로 좁혀** 유지(JO가 이미 잡는 태그된 일반행정과 중복·소음 최소화).
- 두 그물 모두 동일한 정규화 토큰·seq 기지집합으로 dedup(Pass A 먼저 실행 → Pass B는 겹치는
  대법원 세무를 기지로 걸러, 순증분 = 참조조문 없는 하급심 세무).
- 조기 종료 판정은 사건종류 필터와 무관하게 "페이지 전체가 기지인가"로만(필터로 걸러진 신규가
  조기 종료를 잘못 유발하지 않도록).

**한계:** 하급심이 대법원까지 확정되기 전이라도 이제 사건명 그물로 잡히지만, 사건명에 세목이
드러나지 않는 판례(예: "부당이득금")로 세무 라벨도 아니면 여전히 못 잡을 수 있음(드묾).
