# MCP 관리 정책

> 작성일: 2026-05-12
> 목적: 활성 MCP 5개 이내 유지로 200K 컨텍스트 윈도우 보호
> 관련: TAX-007

---

## 1. 핵심 원칙

- **활성 MCP 최대 5개** — 초과 시 컨텍스트 윈도우 압박으로 세법 추론 품질 저하
- **추가 전 컨텍스트 윈도우 영향 평가 필수** — MCP마다 수천~수만 토큰 점유
- **불필요 MCP 즉시 비활성화** — 작업 완료 시 해당 MCP 제거

---

## 2. 현재 활성 MCP 목록

| # | MCP | 역할 | 우선순위 | 활성화 시점 |
|---|---|---|---|---|
| 1 | `shrimp-task-manager` | 작업 관리 + Phase 계획 추적 | 필수 | 프로젝트 시작 |
| 2 | `sequential-thinking` | 복잡한 세법 추론 시 순차 사고 지원 | 필수 | 프로젝트 시작 |

> **현재 2개 — 권장 한도(5개) 이내 충족**

---

## 3. Phase별 추가 계획

| 추가 시점 | MCP | 목적 | 추가 후 총 수 |
|---|---|---|---|
| 외부 API 통합 시 (M3) | `law-go-kr` (자체 구축) | 국세법령정보센터 직접 호출 | 3개 |
| 메타데이터 저장 시 | `supabase` | 검증 로그·골든셋 결과 저장 | 4개 |
| 메모리 영속화 시 | `memory` | 세션 간 세법 컨텍스트 유지 | 5개 |

> 최대 추가 후 총 5개 — 한도 내 유지

---

## 4. 5개 초과 시 처리 프로세스

1. 신규 MCP 추가 필요 시 **기존 MCP 비활성화 검토 먼저**
2. 컨텍스트 윈도우 영향 평가 (200K 토큰 기준)
3. 우선순위 낮은 MCP 비활성화 후 추가
4. 변경 사항 아래 §5 변경 이력에 기록

**비활성화 우선순위 (낮은 것부터):**

| 순위 | MCP | 비활성화 가능 조건 |
|---|---|---|
| 1순위 | `sequential-thinking` | 단순 법령 조회 작업 — 복잡한 순차 추론 불필요 시 |
| 2순위 | `memory` | 세션 내 컨텍스트로 충분한 단기 작업 시 |
| 3순위 | `supabase` | 로그 저장 불필요한 개발·테스트 환경 시 |
