# 법리 관계 검색 세법 챗봇 로드맵 — 평가 요청서

> 목적: 현재 구축된 pgvector·인용 그래프를 바탕으로 **유사 법리, 다른 결론, 반대·변경된 법리까지 탐색하는 세법 챗봇**을 만드는 제안의 타당성을 평가한다.
>
> 상태: 검토용 초안. 이 문서는 구현 승인이나 SSOT·PRD 변경을 의미하지 않는다.
>
> 평가 원칙: `정확성 > 완전성 > 속도 > 편의성`

- 법령 원문을 요약·의역하거나 새로운 세법 결론을 만들지 않는다.

- 대안이 2개 이상이면 추천안을 먼저 두고 각 방안의 장점·단점을 한 줄씩 설명한다.
- 근거가 부족하면 추측하지 말고 `근거 부족`으로 표시한다.

## 2. 평가 대상 제안의 결론

현재 시스템으로 유사 법리·다른 결론을 탐색하는 세법 챗봇을 만들 수 있다. 다만 벡터 유사도만으로 “같은 법리”나 “반대 법리”를 직접 판정하면 안 된다.

권장 발전 순서는 다음과 같다.

```text
유사 쟁점 검색
  → 유사 사실관계 비교
  → 다른 결론 탐색
  → 검수된 법리 변경·폐기 표시
```

핵심 신규 기능은 벡터 DB 자체가 아니라, 검색된 문서 사이의 관계를 판정·검증하는 **법리 관계 레이어**다.

---

## 3. 현재 시스템에 이미 존재하는 기반

저장소 문서 기준으로 다음 기반이 구축돼 있다.

- 판례 10,083건, 심판례 135,810건, 해석례 135,907건 등 약 28만 건 규모의 voyage-4 임베딩 코퍼스
- `taxlaw_embeddings.embedding vector(1024)` 기반 cosine 검색
- 판례·심판례·해석례별 벡터 참고자료 게이트
  - `topK=5`
  - `minSimilarity=0.5`
  - 자료유형별 최대 2건
- 판례·심판례 인용 관계 `citation_edges` 132,381건
- 인용 그래프 1-hop 확장과 피인용수 기반 랭킹 부스트
- 직접검색 다중 쿼리 병합, 법리축·사실축 분리, 본문 관련도 반영
- law-verifier V1~V6
- 뒤집힘 신호 후보 추출 및 회계사 검수 반영 도구

### 현재 한계

1. 전문 임베딩은 주제 유사도를 찾지만 결론의 방향까지 구별하지 못한다.
2. 벡터·그래프 확장 자료는 현재 `references` 전용이며 `citations`로 승격되지 않는다.
3. `citation_edges`의 주된 관계는 `FOLLOWS`, `REFERS`, `APPEAL`이며, 법리 방향의 완전한 분류 체계가 아니다.
4. 뒤집힘 후보 2,796건은 실제 회계사 검수가 남아 있다.
5. 약 28만 행에서 ANN 인덱스 없이 검색하며, 최근 측정상 벡터 3게이트 P95가 4.52초다.
6. 최근 종단 P95는 25.37초로 15초 목표를 초과했고, 주된 원인은 LLM 답변 생성 tail latency다.
7. 긴 문서 일부는 임베딩 입력이 절단되므로 문서 후반 쟁점이 벡터에 충분히 반영되지 않을 수 있다.

## 4. 핵심 설계안

### 4.1 전체 흐름

```text
[1] 사용자 질문
      ↓
[2] 쟁점·사실·시점 구조화(Query Legal Issue Card)
      ↓
[3] 직접검색 + 벡터검색 + 인용 그래프 후보 회수
      ↓
[4] 같은 법적 쟁점·비교 가능한 사실관계인지 리랭킹
      ↓
[5] 법리 관계 판정
      ↓
[6] 시점·Trust Tier·원문 증거·관계 라벨 검증
      ↓
[7] 직접 근거 / 같은 방향 / 구별 사례 / 다른 결론 / 법리 변경 주의사항 출력
```

기존 RAG 5단계는 압축하거나 우회하지 않는다. 위 법리 관계 검색은 기존 검색 단계의 후보 확장 및 참고자료 구성에 추가하되, 답변 노출 전에는 기존 law-verifier와 신규 관계 검증을 모두 통과해야 한다.

### 4.2 법리 카드 파생 데이터

기존 `TaxLaw.content`는 변경하지 않고 별도 파생 테이블을 둔다.

```text
legal_propositions
- id
- documentId / externalId
- sourceType
- issueKeys
- statuteRefs
- factPattern
- holding
- outcome
- conditions
- exceptions
- applicablePeriod
- evidenceSpan
- evidenceHash
- contentHash
- extractorVersion
- reviewStatus
- createdAt / updatedAt
```

#### 불변 조건

- `TaxLaw.content` 원문은 수정하지 않는다.
- `holding`, `factPattern` 등은 원문이 아니라 파생 메타데이터임을 구조적으로 구분한다.
- 모든 파생 판단에는 원문 부분 문자열인 `evidenceSpan`과 원문 해시를 연결한다.
- `evidenceSpan`이 원문에 문자 단위로 존재하지 않으면 파생 데이터를 폐기한다.
- 원문 `contentHash`가 바뀌면 기존 법리 카드와 관계 판정을 무효화하고 재추출한다.

### 4.3 다중 임베딩

전문 임베딩 하나 외에 법리 카드 기준 임베딩을 별도로 둔다.

- `issueEmbedding`: 어떤 법적 쟁점을 다루는가
- `factEmbedding`: 사실관계가 얼마나 유사한가
- `holdingEmbedding`: 어떤 판단·법리를 채택했는가

“반대 법리” 검색은 쿼리 벡터에 음수를 곱하는 방식으로 구현하지 않는다. 먼저 같은 쟁점의 후보를 넓게 검색한 다음, 결론과 근거를 비교해 관계를 판정한다.

### 4.4 관계 분류 체계

| 관계 타입 | 의미 | 사용자 표시 | 자동 노출 조건 |
|---|---|---|---|
| `SUPPORTS` | 같은 쟁점에서 같은 법리·방향 | 같은 방향 자료 | 동일 쟁점·근거 확인 |
| `ANALOGOUS` | 중요 사실관계가 유사 | 유사 사례 | 사실 비교 결과 포함 |
| `DISTINGUISHES` | 중요 사실 차이 때문에 결론이 달라짐 | 구별되는 사례 | 차이점 명시 필수 |
| `OPPOSITE_OUTCOME` | 같은 쟁점에서 다른 결론 | 다른 결론 자료 | 폐기·변경으로 표현 금지 |
| `OVERRULED` | 후속 판례가 종전 법리를 명시적으로 변경 | 변경·폐기된 법리 | 공식 명시 또는 회계사 검수 필수 |
| `SUPERSEDED_BY_LAW` | 법 개정으로 종전 법리 효력 상실 | 입법 변경 주의 | 개정 법령·시점 검증 필수 |
| `UNKNOWN` | 비교 근거 부족 | 관계 확인 불가 | 답변 단정 금지 |

`OPPOSITE_OUTCOME`과 `OVERRULED`를 혼동하지 않는 것이 가장 중요하다. 결론이 다르거나 후속 판례라는 이유만으로 앞선 판례가 폐기된 것은 아니다.

### 4.5 하이브리드 후보 검색

후보는 다음 경로를 병렬로 수집한다.

1. 기존 직접 검색·사건번호 검색
2. 전문 임베딩 검색
3. 쟁점·사실·판단 임베딩 검색
4. 인용 그래프 1~2 hop
5. 명시적 법령·조문 필터
6. 질문의 기준 시점 필터

각 경로의 상위 후보를 병합하고 중복 제거한 뒤 약 30~50건을 리랭커로 보낸다. 리랭커는 다음 기준으로 상위 8~12건을 선정한다.

- 동일한 법적 쟁점인가
- 사실관계가 비교 가능한가
- 질문 시점에 적용 가능한가
- 결론·주문·판단 이유가 충분히 존재하는가

리랭커는 관련도 정렬만 담당하고 법리 관계를 최종 확정하지 않는다.

### 4.6 구조화 관계 판정

관계 판정 결과는 자유문장이 아니라 스키마 검증된 구조화 출력으로 제한한다.

```json
{
  "relationType": "SUPPORTS | ANALOGOUS | DISTINGUISHES | OPPOSITE_OUTCOME | UNKNOWN",
  "sameIssue": true,
  "comparableFacts": true,
  "materialFactDifferences": [],
  "candidateHolding": "",
  "evidenceExcerpt": "",
  "confidence": 0,
  "abstainReason": ""
}
```

`OVERRULED`와 `SUPERSEDED_BY_LAW`는 일반 모델 분류 결과만으로 자동 확정하지 않는다. 명시적 원문 신호와 회계사 검수 결과를 별도 경로로 사용한다.

### 4.7 relation-verifier

기존 law-verifier V1~V6를 변경하지 않고 별도 검증 계층을 추가한다.

| 항목 | 통과 조건 | 실패 시 |
|---|---|---|
| R1. 문서 존재 | 비교 대상이 실제 검색 결과·코퍼스에 존재 | 해당 관계 폐기 |
| R2. 증거 무결성 | 관계 근거 발췌가 원문과 문자 단위 일치 | 해당 관계 폐기 |
| R3. 쟁점 동일성 | 동일하거나 직접 비교 가능한 법적 쟁점 | `UNKNOWN` 처리 |
| R4. 사실 비교 | 중요한 사실 차이가 명시됨 | 단정 표현 금지 |
| R5. 시점·권위 | 적용 법령·결정일·Trust Tier가 정확 | 관계 폐기 또는 경고 |
| R6. 변경 판정 | `OVERRULED`·`SUPERSEDED_BY_LAW`에 공식 근거 또는 검수 존재 | 자동 노출 금지 |

모델 추론만 있는 경우에는 “다른 결론으로 보이는 사례”까지만 허용하고 “법리가 폐기됐다”는 표현을 금지한다.

## 5. 성능 설계

### 5.1 ANN 인덱스 검토

약 28만 건 전체 스캔 상태에서 리랭킹·관계 판정을 추가하면 응답시간이 더 악화될 수 있다. 다음을 먼저 검토한다.

- `source_type`별 partial HNSW 인덱스
- `hnsw.iterative_scan`
- `hnsw.ef_search` 튜닝
- exact 검색과 HNSW 검색의 Recall@K 비교
- source type별 분할 또는 파티셔닝 필요성

HNSW는 속도를 위해 일부 재현율을 포기할 수 있으므로, 현재 exact 검색을 기준선으로 유지하고 골든셋에서 손실을 측정한 뒤 도입한다.

### 5.2 온라인 호출 제한

- 리랭킹 대상: 최대 30~50건
- 관계 판정 대상: 최대 8~12건
- 실제 답변 노출: 관계별 2~3건
- 동일 문서쌍의 관계 판정은 `contentHash + extractorVersion`으로 캐시
- 저신뢰 관계는 자동 노출하지 않고 검수 큐로 전송

### 5.3 문서 청킹

긴 문서를 단순 고정 글자 수로 자르지 않고 가능한 경우 다음 구조를 이용한다.

- 판시사항
- 판결요지·재결요지
- 주문
- 사실관계
- 판단 이유
- 관련 법령

원문 전문은 기존 테이블에 그대로 보존하고, 청크에는 원문 offset·section type·content hash를 기록한다.

## 6. 제안 로드맵

| 단계 | 예상 기간 | 주요 산출물 | 종료 기준 |
|---|---:|---|---|
| 0. 정의·평가셋 | 1주 | 관계 타입, 법리 카드 스키마, 파일럿 쟁점 선정 | 회계사 정의 승인 |
| 1. 파일럿 추출 | 2주 | 한 쟁점군 500~1,000문서 법리 카드 | 원문 증거 일치 100% |
| 2. 검색·리랭킹 | 2주 | 다중 임베딩, HNSW 비교, top50→top12 | Recall@50 ≥ 90% |
| 3. 관계 판정 | 2주 | 관계 분류기, abstain 정책 | 다른 결론 Precision ≥ 95% |
| 4. 검증·UI | 2주 | relation-verifier, 비교 카드 | 과대 변경 판정 0건 |
| 5. 베타·환류 | 2~3주 | shadow mode, 피드백·캐시·P95 측정 | 품질·성능 게이트 통과 |
| 6. 전 세목 확장 | 점진적 | 인기 쟁점순 백필·증분 동기화 | 세목별 골든셋 통과 |

### 권장 진행 순서

1. 운영 로그 축적 여부 확인
2. 기존 `TAX-044`의 세무 도메인 사전·법리축·사실축 설계를 선행 또는 재사용
3. 운영 빈도가 높은 세법 쟁점 1개 선정
4. 질문 30건 × 관계 4종 = 문서쌍 120건 파일럿 골든셋 작성
5. exact 검색과 HNSW·리랭킹 성능 비교
6. 내부 비교 화면에서 shadow mode 운영
7. 뒤집힘 후보 2,796건 중 검색 빈도·피인용수가 높은 상위 100~200건부터 회계사 검수
8. 관계 검증 통과 후 챗봇 답변에 단계적으로 노출

### 예상 사용자 출력

```text
① 직접 적용 법령
② 같은 방향의 유사 사례
③ 사실관계가 달라 구별되는 사례
④ 같은 쟁점에서 다른 결론을 낸 사례
⑤ 법리 변경·법 개정·시점 주의사항
```

## 7. 평가 지표 제안

| 영역 | 제안 지표 | 목표 |
|---|---|---:|
| 후보 회수 | Recall@50 | ≥ 90% |
| 최종 정렬 | nDCG@10 또는 MRR@10 | 기준선 대비 개선 |
| 다른 결론 판정 | Precision | ≥ 95% |
| 법리 변경 판정 | False Positive | 0건 |
| 증거 원문 일치 | 문자 단위 일치율 | 100% |
| 시점 정확성 | 적용 시점·결정일 정확도 | ≥ 95% |
| 환각 | 미검색 자료 인용률 | 0% |
| 성능 | 신규 관계 기능 추가 지연 | P95 +2초 이내 |
| 종단 성능 | 전체 응답시간 | P95 < 15초 |

낮은 recall보다 잘못된 “반대·폐기 법리” 표시가 더 위험하므로, 관계 판정은 abstain을 적극 허용하고 precision을 우선한다.
