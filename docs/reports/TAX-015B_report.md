## 배경

TAX-015 진단에서 확인된 한계: 국세법령정보시스템 출처 판례는 **목록 메타만 제공하고 본문(판시사항·판결요지)을 제공하지 않는다.** 발췌 인용(citation)은 원문과 문자 단위 일치(CLAUDE.md §6.1)가 필수이므로, 본문이 없으면 인용 자체가 불가능하다. TAX-015에서는 이런 판례를 **결과에서 제외**했는데, 양도소득세 등 실무 핵심 세법 판례가 다수 국세 출처라 회계사가 "관련 판례가 존재한다"는 사실조차 보지 못하는 문제가 있었다.

본 티켓은 본문 없는 비법령 자료를 **발췌 인용이 아닌 "참고 목록(references)"** 으로 분리해, 사건명·선고일·원문 링크만 ⚪참고자료로 노출한다. 참고 목록은 발췌가 없으므로 V2 대상이 아니고, 검색 결과 원본(메타)이라 환각 위험이 없다.

## 구현 핵심: citable / references 분리 규칙

`splitResults()`의 분기는 다음 한 가지 기준으로 결정된다:

| 자료 | 본문(content) | 처리 |
|---|---|---|
| 법령 | 있음 | `citable` (LLM 발췌 인용 + V1~V6 검증) |
| 판례·해석례·심판례 | 있음 | `citable` (LLM 발췌 인용 + V1~V6 검증) |
| 판례·해석례·심판례 | **없음** | `references` (⚪참고 목록, 발췌 없음, 최대 5건) |
| 법령 | **없음** | **드롭** (비정상 데이터 — 본문 없는 법령은 있을 수 없음) |

핵심은 **본문 없는 자료를 LLM에 절대 전달하지 않는다**는 점이다. LLM이 본문 없는 자료로 발췌를 "지어내면" 환각이 되므로, 발췌가 가능한 자료(citable)만 LLM에 주고, 나머지는 검색 결과 원문 그대로(메타) 참고 목록에 첨부한다.

## 회귀 수정 (AC#3)

본 작업 검증 중 통합 테스트 1건 실패를 발견·수정했다.

- **무엇:** `tests/integration/nationalTaxLaw.test.ts` > "[판례] 법원 출처 판례는 본문·메타·T4·키없는 링크를 가진다"가 `result.items.find(i => i.sourceType === '판례')`로 **첫 판례**를 잡아 대법원 판례라고 단정.
- **왜:** TAX-015 시점엔 본문 없는 판례를 제외해 판례가 대법원 1건뿐이라 `.find()`로도 정확히 잡혔다. TAX-015B부터 국세 출처 판례도 반환되며 판례가 2건이 되고, `sortPrecedents`(선고일↓) 정렬상 더 최근인 인천지방법원 판례(2026-04-14)가 대법원 판례(2026-03-12)보다 앞에 와서 `.find()`가 의도와 다른 판례를 집었다.
- **판단:** 프로덕션 코드는 SSOT §7.7 결정론 정렬 규칙대로 정상 동작. 깨진 것은 "첫 판례=대법원"이라는 테스트의 암묵적 가정이며, 티켓 §3.1("검증/테스트 정합") 범위.
- **조치:** 테스트가 사건번호(`2020다288436`)로 대법원 판례를 명시 지목하도록 수정. 단정 대상이 명확해져 정렬 순서 변경에 견고해짐.

## 잠재 위험 / 한계

- **참고 목록 5건 상한:** 본문 없는 판례가 많은 쟁점에서는 일부가 잘릴 수 있다. 정렬은 선고일↓로 결정론적이므로 잘리는 항목도 일관적이나, 회계사가 더 많은 목록을 원할 경우 상한 조정 필요.
- **참고 목록 시점 라벨:** references는 답변 전체 시점 라벨(`temporalLabel`)에 종속되지 않으며 개별 시점 라벨을 갖지 않는다. 판례 선고일만 표기.
- **국세 출처 판례 본문 자체는 여전히 미제공:** 본 티켓은 "존재를 노출"할 뿐 본문을 가져오지는 못한다(공식 API 한계). 회계사는 원문 링크로 직접 확인해야 한다.
- **호출 수:** 판례 조회 건수 확대(3→10)로 본문 조회(법원 출처마다 추가 호출)가 늘 수 있다. 응답 지연·요청 한도 모니터링 필요.
