## 0. 한 줄 결론

> **채택 가능하다. 단, 원본의 "키워드 근사 역방향"은 우리 정확성 원칙(§2)과 충돌하므로
> 그대로 베끼지 않는다.** 대신 우리 API가 주는 **명시 연계 필드(심판례 `관련법령`)** 와
> **조문 본문 인용 파싱(정방향)** 을 토대로 "검증된 그래프"를 만든다. 키워드 검색은 후보
> 수집용 보조로만 쓰고, 엣지는 원문 명시로 검증된 것만 🟢, 나머지는 🟡/⚪로 강등한다.

## 1. 원본 impact_map의 실제 구현 (소스 확인)

`src/tools/impact-map.ts` → 중심 조문(`${lawName} ${jo}`)에 대해 6개 병렬 호출:

| 호출 | 방향 | 실제 방식 | 정확성 |
|---|---|---|---|
| `searchPrecedents` | 역방향 | **`query="법령명 조문번호"` 키워드 검색** | ⚠️ 근사(인용 보장 X) |
| `searchInterpretations` | 역방향 | 키워드 검색 | ⚠️ 근사 |
| `searchAdminAppeals` | 역방향 | 키워드 검색 | ⚠️ 근사 |
| `searchConstitutionalDecisions` | 역방향 | 키워드 검색 | ⚠️ 근사 |
| `searchOrdinance` | 역방향 | 키워드 검색(자치법규) | ⚠️ 근사 + 세법 범위 밖 |
| `getArticleDetail` + `extractCitedLaws` | 정방향 | **조문 본문에서 `「OO법」` 정규식 파싱** | ✅ 원문 명시 |

- 정방향 정규식: `/「([^」]{2,40}?(?:법|법률|시행령|시행규칙|규칙|규정))」/g`
- 결과를 `buildMermaid()`로 `graph LR` mermaid 코드화(역방향=실선, 정방향=점선 `-.인용.->`).
- **핵심 한계**: 역방향 5종이 전부 키워드 근사 → "그 판례가 진짜 이 조문을 인용했는지" 보장 못 함.

## 2. 우리 API 실호출 진단 결과 (2026-05-24)

`scripts/diagnostics/impact_map_probe.mjs` (읽기 전용, 키 미포함).

### [진단 1] 정방향 — 조문 content 인용 파싱 = ✅ 가능
TAX-032로 이미 확보한 조문 content에 원본과 동일 정규식 적용:
| 조문 | content 길이 | 추출된 「OO법」 |
|---|---|---|
| 소득세법 제104조 | 7,203자 | 「주택법」 (1종) |
| 부가가치세법 제26조 | 1,550자 | 「뉴스통신 진흥에 관한 법률」·「담배사업법」·「공동주택관리법」·「주택법」 (4종) |
→ **추가 API 호출 0건**으로 정방향 인용 추출 가능. 원문 명시라 신뢰도 높음.
→ 단, `「법」` 외부참조만 잡힘. "제104조의3"(같은 법 내부 조문)은 별도 패턴 필요(원본도 분리 처리).

### [진단 2] 역방향(근사) — 키워드 검색 = ⚠️ 부정확 실증
"소득세법 제104조" vs "소득세법" 검색 비교:
| 트랙 | "법령명 조문번호" | "법령명만" | 관찰 |
|---|---|---|---|
| 판례 | 4건 | 5건 | 제155조·제168조의6 등 **다른 조문 판례 혼입** |
| 심판례 | 5건 | 5건 | 조문번호 유무로 결과 거의 불변 |
| 법제처해석 | 1건 | 5건 | — |
→ 조문번호를 넣어도 다른 조문 사건이 섞임 = **키워드 근사는 인용 연계를 보장하지 않음**(원본 한계 확인).

### [진단 3] 역방향(정밀) — API 명시 연계 필드 = ✅✅ 핵심 수확
| 트랙 | 본문 제공 | 연계 필드 | 값 예시 |
|---|---|---|---|
| **심판례**(ttSpecialDecc) | ✅ | **`관련법령`·`참조결정`·`세목`** | `관련법령: 「조세특례제한법」 제69조` |
| 판례(prec) | ❌(세법은 국세 출처라 본문 미제공) | 참조판례·참조조문 확인 불가 | — |
| 법령해석례(expc) | ✅ | 명시 연계 필드 없음(안건명·질의요지·회답·이유만) | 본문 텍스트에 「소득세법」제104조 언급은 있음 |

심판례 본문 전체 키:
`[재결청, 청구취지, 참조결정, 재결요지, 이유, 따른결정, 의결일자, 사건명, 주문, 세목, 데이터기준일시, 처분청, 사건번호, 특별행정심판재결례일련번호, 청구번호, 재결례유형코드, 재결례유형명, 관련법령, 처분일자]`

→ **심판례 `관련법령`은 「법령명」 제N조 형식의 원문 명시 연계** = 키워드 추정이 아닌 진짜 데이터.

## 3. 정확성 등급 결론 (트랙별)

| 그래프 엣지 | 데이터 출처 | 신뢰 라벨 | 비고 |
|---|---|---|---|
| 조문 → 인용 법령(정방향) | 조문 content `「OO법」` 파싱 | 🟢 직접(원문 명시) | 추가 API 0 |
| 조문 ← 심판례(역방향) | 심판례 `관련법령` 필드 검증 | 🟢 가능 | 키워드 후보를 `관련법령` 일치로 필터 |
| 조문 ← 판례(역방향) | 키워드 근사(본문 대부분 미제공) | 🟡/⚪ | 단정 금지 |
| 조문 ← 법령해석례(역방향) | 키워드 근사 + 본문 텍스트 언급 | 🟡/⚪ | 단정 금지 |

> **설계 원칙: 키워드로 후보 수집 → 원문 명시 연계(`관련법령`·content 파싱)로 검증된 것만 🟢.
> 검증 불가 엣지는 🟡/⚪로 강등하고 "추정 관계"임을 명시.** (CLAUDE.md §6.3 라벨링)

## 4. 채택/기각 (원본 대비)

### 🟢 채택 (우리 방식으로 변형)
- **정방향 인용 파싱**: 조문 content → `「OO법」` + `제N조` 추출. (추가 API 0, 원문 명시)
- **역방향 심판례 연계**: 키워드 후보 → `관련법령` 필드로 정밀 검증한 엣지.
- **mermaid 시각화**: `graph LR` 코드 생성(역방향=실선, 정방향=점선).

### 🔖 보관/주의
- 역방향 판례·해석례: 본문 미제공 다수 → 🟡/⚪ 참고로만. 과신 금지.
- 같은 법 내부 조문 참조(제N조의M): 별도 패턴 필요(2차 범위).

### ❌ 기각 (원칙 위반/범위 밖)
- 자치법규(조례) 트랙: 세법 범위 밖.
- 헌재·행정심판 별도 트랙 신설: 현 자료원에 없음(Post-MVP).
- **"키워드 근사 = 직접 인용" 단정**: §2 정확성 위반(원본의 핵심 약점).

## 5. 아키텍처·원칙 정합 (예비 검토)

- 그래프 조립은 **검색 후보의 관계 재구성** → 새 Usecase(`buildImpactMap`) 또는 어댑터 보강.
- 원문 보존(§6.1): `관련법령`·인용 텍스트를 **문자 그대로** 노드 라벨로. 의역·요약 금지.
- 라벨링(§6.3): 엣지마다 🟢/🟡/⚪ 부착 — "추정"과 "명시"를 시각적으로 구분.
- RAG 5단계(§5): impact_map은 별도 보조 기능 → 기존 검색→검증 파이프라인을 **우회하지 않음**.
  (그래프에 노출되는 발췌가 생기면 V1~V6 대상 여부를 티켓에서 확정.)
- 정답 자동확정 금지: 그래프는 "관계 지도"이지 "세법 정답"이 아님 → 회계사 판단 보조.
