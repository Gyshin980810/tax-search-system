## 2. 문제 정의

Phase 6A 1차 검수(PHASE6A-REVIEW_report.md)에서 G4-03·04·06 3건이 V1~V6 정적 검증을 통과하면서도 **거짓 전제 수용** 패턴을 보였다.

| 케이스 | 질문의 거짓 전제 | 이전 summary 문제 |
|---|---|---|
| G4-03 | 매출 3억 이하 소매업 부가세 전액 면세 조항 | "면세 혜택을 받을 수 있다는 점이 명시되어 있습니다" |
| G4-04 | 3대 가업상속 시 상속세 전액 면제 특례 | "면제를 받을 수 있습니다" |
| G4-06 | 형제자매 간 5,000만원 이하 증여 비과세 | 거짓 전제 수용하는 ANSWERED 응답 |

인용 자체는 정상(V1 통과)이라 기존 V1~V6로는 감지 불가한 사각지대였다.

## 3. 해결 전략 선택

**방안 A (채택)**: SYSTEM_PROMPT 전제 검증 지침 추가 → 단건 재실측 → V7 필요 여부 결정

**방안 B (미채택)**: SYSTEM_PROMPT + V7 동시 추가 — 오탐 위험(정상 답변 차단)이 있어 프롬프트 1차 방어를 우선 검증 후 결정하기로 함.

## 4. 구현 내용

### 4.1 SYSTEM_PROMPT 추가 지침

`src/adapters/llmAnswerGenerator.ts` SYSTEM_PROMPT 끝에 아래 섹션 추가:

```
[질문 전제 검증 규칙 — TAX-6A-8]
질문에 "~라는 조항이 있나요?", "~하면 면제된다는 규정이 있나요?" 등 사실 주장이 전제로 포함된 경우:
1. 제공된 조문에서 그 전제를 직접 뒷받침하는 근거를 찾아라.
2. 근거가 없으면 summary 첫 문장에 반드시 "질문에서 언급한 [전제 내용]에 해당하는 조항을 찾지 못했습니다."를 명시하라.
3. 유사 제도(간이과세·가업상속공제 등)가 있더라도, 전제(전액 면세·전액 면제·비과세 등)와 내용이 다르면 그 차이를 명확히 서술할 것.
4. 직접 근거 없이 질문의 전제를 사실처럼 되풀이하거나, "~받을 수 있습니다" 등으로 가능성을 시사하지 말 것.
```

## 7. 방어 방식 및 한계

### 방어 구조 (3중)
1. **SYSTEM_PROMPT 전제 검증 지침** (1차 — 본 티켓으로 구현): LLM이 거짓 전제를 인식하고 "찾지 못했습니다"로 응답
2. **기존 V1~V6** (2차): 환각 인용·라벨 오류·단정 표현 차단
3. **회계사 최종 판단** (3차): 시스템 응답의 사실관계 최종 검토

### 한계
- 프롬프트 기반 방어는 LLM 비결정성에 의존 — 약 5~10% 확률로 지침 무시 가능
- "~라는 조항이 있나요?" 형태 이외의 거짓 전제(예: "당연히 ~이죠?") 패턴은 별도 관찰 필요
- 규칙 기반 V7 추가는 오탐 위험으로 보류 — 재발 시 별도 티켓으로 검토
