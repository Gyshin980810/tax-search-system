- 진단 스크립트: `scripts/diagnostics/article_dump.mjs` (신규, 읽기 전용, 키 미포함).
- 부가세 제26조·소득세 제55조·지방세 제11조 3개를 실측해 다음을 확정:

| 발견 | 내용 | 설계 반영 |
|---|---|---|
| **번호 중복** | `항번호="①"`인데 `항내용`도 `"① 다음…"`으로 시작. 호·목도 동일 | 번호를 **prepend하지 않음**(내용에 이미 포함) |
| **세율표(중첩 배열)** | 소득세 제55조 `항내용` = `array[1]<array[29]<string>>` (괘선이 줄별 요소) | 배열은 `\n`으로만 결합 → 괘선 원문 복원 |
| **목(目) 존재** | 지방세 제11조 호[0]에 `목`(`목번호`·`목내용`) | 조문→항→호→목 4단계 재귀 조립 |
| **단수/복수 혼재** | 항·호·목이 단일 객체 또는 배열로 옴 | `toArrayNode`로 정규화 |

## 1. 변경 사항 요약

### 파일 변경 목록
- `src/adapters/nationalTaxLaw.ts` (수정) — 항·호·목 타입 정의 + `flattenText`·`assembleArticleContent` 헬퍼 + `fetchArticles` content 조립부.
- `scripts/diagnostics/article_dump.mjs` (신규) — 항·호·목 구조 정밀 덤프 진단(읽기 전용).
- `tests/unit/articleAssembly.test.ts` (신규) — 조립 순수 함수 단위 테스트 7케이스.
- `tests/integration/nationalTaxLaw.test.ts` (수정) — 어댑터 경로 조립 통합 케이스 2건 추가(시나리오 9).

### 주요 변경
1. **타입 보강**: `RawArticle`에 `항?: RawHang | RawHang[]` 추가. `RawHang`(항번호·항내용·호),
   `RawHo`(호번호·호내용·목), `RawMok`(목번호·목내용), 재귀 `NestedText`(문자열 | 중첩 배열) 정의.
2. **`flattenText(value)`**: 문자열은 그대로, (세율표 등) 중첩 배열은 원문 줄 순서를 유지한 채
   `\n`으로만 결합. 요약·의역·재배열 없음.
3. **`assembleArticleContent(article)`**: `조문내용`(제목) → 항내용 → 호내용 → 목내용을
   원문 순서·문자 그대로 결합. 번호 prepend 금지(중복 방지), 빈 노드 스킵.
4. **`fetchArticles`**: `content`를 `조문내용` 단독 → `assembleArticleContent(article)`로 교체.
   `parseArticleHead`(제목 파싱)는 여전히 `조문내용`만 사용 → articleNumber·articleTitle 무오염.

### 아키텍처·원칙 정합
- 항·호·목 조립은 **외부 API 응답 정규화 = Adapter 계층 책임** → §4 위반 없음.
- 검증[4]·law-verifier **무변경**(검색 본문 완전화이지 검증 변경 아님).
- **원문 보존(§6.1·V2)**: 항내용·호내용·목내용 텍스트를 문자 그대로 결합. 축약·의역·표 재구성 없음.
  결합 구분자는 `\n`(가장 중립적). 발췌(excerpt)는 회계사가 골든셋 워크플로우에서 핵심부로 좁힘.
- 비법령 4트랙(판례·해석례·심판례) **무변경**(범위 최소화).

## 3. 잠재 위험
- **content 비대화**: 항·호 많은 조문(양도 제104조 7,203자)은 토큰↑. 무결성 우선이라 허용하되,
  발췌(excerpt)는 회계사가 핵심부로 좁힘(골든셋 워크플로우). content(원문)는 그대로 보존.
- **`<img>` 태그·flDownload 링크 포함**: 세율표 원문에 이미지 참조가 섞여 옴. 원문 보존 원칙상 제거하지 않음
  (제거 = 원문 변형). 표 텍스트는 별도로 모두 들어있어 의미 손실 없음. 표시 단계에서 처리 여부는 별도 판단.
- **새 키 출현 가능성**: 일부 법령에 미관측 하위노드가 있을 수 있음. `flattenText`가 문자열·배열만 처리하고
  그 외는 ''로 안전 폴백 → 신규 키는 누락될 뿐 깨지지 않음(보수적). 발견 시 STOP & ASK.
