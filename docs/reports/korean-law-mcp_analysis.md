## 0. 한 줄 결론

> **가져올 것은 "도구 17개"가 아니라 "기법 2개"다.** 그 둘이 우리가 막혀 있던 두 통증
> (지방세법→지방교부세법 오매칭 / content가 제목만 옴)을 정확히 푼다.
> 단, korean-law-mcp의 "원문 축약"은 우리 §6.1 위반이라 **절대 도입하지 않는다**.

## 1. 두 시스템의 본질 차이

| 구분 | korean-law-mcp | 우리 tax-search-system |
|---|---|---|
| 정체성 | LLM에 법령 도구를 노출하는 **범용 MCP**(17 도구, 42 API) | 세법 한정 **정확성 보증 RAG**(검증 V1~V6) |
| 인용 | 판례 '이유' **800자+중략+400자 축약** | **원문 문자 단위 일치**(§6.1) |
| 통제 | LLM 자유 도구 호출(chain_*) | **RAG 5단계 고정**(압축·생략 금지) |

→ 그들의 핵심인 "축약·자유체인"은 우리 원칙과 상충. **기법만 선별 이식**한다.

## 2. korean-law-mcp 핵심 기법 (확보)

1. **약칭 사전(LAW_ALIAS_ENTRIES 52+)** + `scoreLawRelevance()` — 동음이의 법령 구분.
2. **JO 코드 변환(제38조→003800) + jo/hang/ho 파라미터** — 조문 정밀조회.
3. **verify_citations** — 인용 정규식 추출 → 30자 lookback → DB 대조 → ✓/✗/⚠.
4. 캐시(검색 1h/전문 24h), 50KB 응답 절단, 17개 결정 도메인 통합.

## 3. JO 실호출 진단 결과 (2026-05-24) — 가설 검증

`scripts/diagnostics/jo_probe.mjs`로 추측 없이 실측. **세 가지 사실 확정:**

### 사실 1. JO 파라미터는 역효과 (가설 기각)
| 조문 | JO 없이 `항` | JO 지정 시 `항` |
|---|---|---|
| 부가세 제26조 | ✅ 2개 | ❌ 0자(사라짐) |
| 소득세 제55조 | ✅ 2개 | ❌ 0자(사라짐) |
→ **JO 경로 폐기.**

### 사실 2. 통증 B 진짜 원인 = 응답에 온 `항`을 어댑터가 무시
- `항` 하위노드는 JO 없이도 응답에 이미 존재(부가세 2·소득세 2·지방세 5).
- 어댑터가 `조문내용`(제목만)만 쓰고 `항[].항내용`을 버림.
- → **추가 API 호출 0건**으로 항·호 조립하면 해결(TAX-032).
- ⚠️ 난관: `항내용`이 문자열/중첩배열(세율표) 혼재 + `호` 별도 → 원문보존 평탄화 필요.

### 사실 3. 통증 A는 한 줄로 해결 실증
```
지방세법 검색 → [0] 지방교부세법(오답) / [3] 지방세법(정답)
laws.find(l => l.법령명한글 === keyword) ?? laws[0]  // [3] 정확 선택 확인
```
→ 정확매칭 + 약칭 사전(TAX-031).

## 5. 아키텍처·원칙 정합

- 약칭·정확매칭·항조립은 전부 **Adapter 계층 정규화** → §4 위반 없음.
- 원문 보존(§6.1): 조립 본문도 **문자 그대로**. 축약·재구성 금지.
- 검증[4]·law-verifier **무변경**(검색 품질 개선이지 검증 변경 아님).
- 정답 자동확정 금지: 매칭/조립은 "검색 후보 품질"이지 "세법 정답"이 아님 → 골든셋 게이트·회계사가 확정.
