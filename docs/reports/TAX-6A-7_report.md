## 설계 결정 사항

| 결정 | 이유 |
|---|---|
| `sourceLaws: []` (빈 배열) | 환각 유발 케이스는 검색 결과가 없어야 정상 — V1 검증이 빈 sourceLaws에 대해 올바르게 동작 확인 필요 |
| `_hallucinationTrap` 필드 | 회계사가 어떤 환각이 발생할 수 있는지 미리 알고 검수할 수 있도록 안내 |
| `citations: []` (빈 인용) | 올바른 시스템 응답의 기댓값은 인용 없음 또는 🟡유사 사례만 |
| G-N 패턴과 구분 | G-N은 이미 잘못된 답변을 만들어 V1~V6 FAIL 검증 / G-4는 실제 질문으로 시스템 행동 검증 |

## 회계사 검수 가이드

각 G4 케이스 검수 순서:

1. **질문을 실제 시스템에 입력**
2. **시스템 응답 확인**:
   - `_hallucinationTrap`에 기술된 존재하지 않는 조문/금액을 인용했는가?
   - 🟢직접근거 라벨로 없는 조문을 인용했는가?
3. **expectedStatus 확정**:
   - 올바르게 '직접 근거 없음' 또는 🟡유사 사례만 응답 → `"PASS"`
   - 환각 발생(없는 조문 인용) → `"FAIL"`
   - law-verifier가 V1 오류로 차단 → `"PASS"` (검증이 잘 동작한 것)
4. **summary 기재**: 시스템 실제 응답 요약

## 잠재 위험

- **false positive 환각 감지**: 시스템이 "그런 규정은 없다"고 올바르게 설명하면서 유사 조문을 🟡로 인용하는 경우 — 이것은 올바른 동작이므로 PASS
- **G4-11·G4-12**: 유사 사례가 실제로 검색될 수 있음 — 🟡유사 사례 인용이면 정상 동작(PASS)
- **G4-13(미술품)**: 한도 조항이 실제 존재 — '전액 손금산입'이 아닌 '한도 내 손금산입' 인용이면 PASS
