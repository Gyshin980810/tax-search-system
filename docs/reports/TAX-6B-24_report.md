## 1. 근본 원인 (프로브로 실측 확정)

TAX-042G(`enforceAxisCombination`)가 검색어를 "법리축 + 사실축" 결합형("법인세법" → "법인세법 손비")으로 만들고, 이 결합 키워드가 그대로 `searchLaws`의 `query` 파라미터에 들어갔다.

`lawSearch.do`의 `query`는 **법령명**을 매칭하므로 "법인세법 손비"라는 법령명이 없어 **결과 0건**이 되고, `fetchArticles`는 `nationalTaxLaw.ts:659`에서 즉시 빈 결과를 반환했다. 즉 정밀도 저하(fallback)를 넘어 **법령 트랙 재현율 완전 실패**였다.

### 실측 프로브 결과 (law.go.kr 라이브 호출)

| 입력 키워드 | (A) 현재[원본 검색] | (B) TAX-6B-24[법리축 분리] |
|---|---|---|
| `법인세법 손비` | **0건** (완전 실패) | 3건, 선택="법인세법" **[exact]** |
| `지방세법 취득세` | **0건** (완전 실패) | 5건, 1위="지방교부세법"이나 선택="지방세법" **[exact]** |
| `상속세 및 증여세법 상속공제` | **0건** (완전 실패) | 3건, 선택="상속세 및 증여세법" **[exact]** |
| `법인세법` (순수 법령명) | 3건, "법인세법" [exact] | 3건, "법인세법" [exact] (**회귀 0건**) |

> "지방세법 취득세" 케이스는 (1) 결합 키워드가 0건임과 (2) 법리축 분리 후 후보 1위가 여전히 동음이의 "지방교부세법"이지만 `selectBestLaw`가 exact로 "지방세법"을 정확히 골라냄을 동시에 증명 — TAX-031(정확매칭)과 TAX-6B-24가 함께 작동한다.

## 2. 변경 사항

### 파일 변경 목록
- `src/domain/lawAliases.ts` (수정): 순수 함수 `splitLegalAxis(keyword)` + `LegalAxisSplit` 타입 추가
- `src/adapters/nationalTaxLaw.ts` (수정): `fetchArticles`가 `splitLegalAxis`로 법리축만 추출해 `searchLaws`·`selectBestLaw`에 전달
- `tests/unit/lawAliases.test.ts` (수정): `splitLegalAxis` 단위 테스트 8건 추가

### 주요 변경
- **`splitLegalAxis`**: 공백 토큰화 후 "~법" 패턴(`/^[가-힣]+법$/`)에 맞는 **마지막** 토큰을 법령명 끝으로 보고, 처음~그 토큰까지를 법리축으로 묶는다(다단어 법령명 "상속세 및 증여세법" 보존). "시행령"/"시행규칙" 후행 토큰은 흡수한다. "~법" 토큰이 없으면 입력 전체를 legalAxis로 통과(회귀 0건).
- **사실축 미소비**: 본 티켓은 법령 선택 정확도만 다룬다. 사실축을 `SearchResult`에 실어 나르지 않고(최소 변경 §9 7), 조문 단위 선별이 필요한 TAX-6B-25가 `splitLegalAxis`를 재호출해 재도출한다(순수 함수라 등가).

## 4. 기대효과

- 복합형 질문("법인세법상 접대비 손금 한도")에서 법령 트랙이 **0건 → 정상 조문 반환**으로 복구 → RAG [2]단계 재현율 직접 상승.
- 동음이의 오매칭("지방세법"→"지방교부세법") 재발 차단 → T1 직접 근거 정확도 보장.
- TAX-031(정확매칭)과 TAX-042G(축 결합)의 충돌 해소.

---

## 5. 잠재 위험·제한

- **본 티켓 단독 효과는 "올바른 법령 선택"까지**다. 선택된 법령의 **전체 조문**이 여전히 반환되며(조문 단위 추림 없음), 관련 조문 선별은 TAX-6B-25 몫이다.
- `splitLegalAxis`는 "~법"으로 끝나지 않는 법령 표현(예: "법인세 시행령", "국제조세조정에 관한 법률")을 법리축으로 인식하지 못하고 입력 전체를 통과시킨다. 회귀는 없으나(기존 동작 유지) 최적은 아니다 — 필요 시 후속 티켓에서 사전 기반 인식으로 보강.
- 프로브 스크립트는 스크래치패드 전용(레포 미포함).
