# TAX-6A-9 진단 리포트 — 법령 연혁 API 지원 여부

**작성일**: 2026-06-14  
**진단 스크립트**: `scripts/diagnostics/law_history_probe.mjs`  
**대상 API**: https://www.law.go.kr/DRF/

---

## 1. 진단 목적

Phase 6A 골든셋 G-3 시점 검색이 구조적으로 실패(T1 직접근거 0건, 13/20 E-VERIFY-FAIL)하는 근본 원인은 API가 현행 법령만 반환하기 때문이다. TAX-6A-9는 과거 시행본 조회가 가능한지 API를 실측하고, 가능하면 어댑터를 확장한다.

---

## 2. 진단 가설 및 실측 결과

### 가설 A: `display=20`으로 과거 lsiSeq 반환 여부

```
GET /DRF/lawSearch.do?target=law&query=법인세법&display=20

totalCnt=3  반환 건수=3
  lsiSeq=276111  법인세법        공포=20251001  시행=20260102
  lsiSeq=283635  법인세법 시행령  공포=20260227  시행=20260227
  lsiSeq=284993  법인세법 시행규칙 공포=20260320  시행=20260320
```

**결과: ❌** — 현행 버전 3종만 반환. 과거 lsiSeq(2018년 개정 전) 미포함.

---

### 가설 B: `efYd` 파라미터 (특정 시행일자 기준 법령 조회)

```
GET /DRF/lawSearch.do?target=law&query=법인세법&efYd=20171231
GET /DRF/lawSearch.do?target=law&query=법인세법&efYd=20181231

totalCnt=3  반환 건수=3 (두 경우 모두)
  → efYd=20171231 이나 efYd=20181231 이나 동일한 현행 lsiSeq 반환
```

**결과: ❌** — `efYd` 파라미터가 API에 의해 무시됨. 현행만 반환.

---

### 가설 C: `lawService.do?MST={lsiSeq}&efYd=20171231` (조문 조회 시 시행일자 지정)

```
GET /DRF/lawService.do?target=law&MST=276111&efYd=20171231
→ 공포일자=20251001  시행일자=20251001  (efYd 무시됨)
```

**결과: ❌** — efYd 파라미터 무시. 현행 조문(2025년 시행본)만 반환.

---

### 가설 D: `LIC` (법령고유ID) 파라미터로 연혁 버전 목록 조회

```
GET /DRF/lawSearch.do?LIC=001563  (법령ID)
→ totalCnt=5585  법인세법 무관한 법령 목록 반환 (필터 아님, 전체 인덱스처럼 작동)
```

**결과: ❌** — `LIC` 파라미터가 법령 고유 필터로 동작하지 않음.

---

### 가설 E: `lawHistory.do` 연혁 전용 엔드포인트

```
GET /DRF/lawHistory.do?LIC=001563
→ 빈 응답 (엔드포인트 없음)
```

**결과: ❌** — 해당 엔드포인트 존재하지 않음.

---

### 가설 F: `JO` 파라미터 (조문번호 직접 지정)

```
GET /DRF/lawService.do?target=law&MST=276111&JO=55
→ 조문 0건 반환
```

**결과: ❌** — `JO` 파라미터 무시됨.

---

## 3. 최종 진단 결론

**www.law.go.kr/DRF/ API는 현행 법령만 반환한다.**

| 시도한 방법 | 결과 |
|---|---|
| `display=20` 다수 버전 | ❌ 현행 3종만 |
| `efYd` 파라미터 | ❌ API가 무시 |
| `lawService.do?efYd` | ❌ API가 무시 |
| `LIC` 연혁 필터 | ❌ 필터 아님 |
| `lawHistory.do` 엔드포인트 | ❌ 없음 |
| `JO` 조문번호 지정 | ❌ 무시 |

→ API 레벨에서 과거 시행본 조회는 **구조적으로 불가능**하다.

---

## 4. G-3 골든셋 영향

G-3 20건 전체가 `targetDate`를 포함하며, 핵심 케이스들은 모두 "과거 시행본 T1 인용"을 전제로 설계됐다:

- G3-01·02: 법인세율 2017/2019년 — 연혁 조문 필요
- G3-03·04: 소득세 최고세율 2017/2019년 — 연혁 조문 필요
- G3-05~G3-20: 공제 한도·신고기한 등 — 연혁 조문 필요

현행 API 구조에서 G-3 시점 정확도 ≥95% 합격선은 **달성 불가**다.

---

## 5. 대안 선택지 (회계사 결정 필요)

### 방안 A — G-3 케이스 재정의 (Phase 6A 즉시 완결)

G-3 골든셋을 "현행 조문 + `[현행]` 라벨"로 정상 처리할 수 있는 케이스만 남기고, 과거 시행본이 필요한 케이스는 "연혁 안내 FAIL 케이스" 또는 "범위 외" 처리.

- **장점**: 추가 구현 없음, Phase 6A 즉시 완결 가능
- **단점**: 과거 귀속연도(경정청구·소급 사안)에서 T1 인용 불가 → 회계사가 법제처 직접 확인 필요

### 방안 B — 스냅샷 DB 적재 (Phase 7 이상, 별도 마일스톤)

핵심 법령(법인세법·소득세법 세율표, 주요 공제 한도 등) 연혁 데이터를 직접 수집해서 pgvector DB에 적재, targetDate 기준 조회.

- **장점**: 과거 T1 인용 가능 → 경정청구·소급 업무 자동화
- **단점**: 데이터 수집 공수 상당(법령마다 수십 버전 수작업), Phase 6A 외 별도 마일스톤 필요
